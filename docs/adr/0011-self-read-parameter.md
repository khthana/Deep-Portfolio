# ADR-0011 — "ฉันคือใคร" มาจาก session แต่เส้นที่ประกาศไว้แล้วว่ารับจาก query ก็ตรวจได้

- **สถานะ**: ตัดสินแล้ว 11 สิงหาคม 2569
- **ที่มา**: [issue #40](https://github.com/khthana/Deep-Portfolio/issues/40)
- **เกี่ยวข้อง**: [ADR-0001](0001-portfolio-access.md) (`requireSelf` เกิดที่นั่น),
  [ADR-0003](0003-enrolment-access.md) (การอ่านของกลุ่มเรียนอ่านนักศึกษาจาก session),
  [#41](https://github.com/khthana/Deep-Portfolio/issues/41) (สามเส้นที่เหลือ)

## บริบท

`GET /user` และ `GET /student/enrolled/subjects` เป็นสองเส้นสุดท้ายที่รับ id ของ
"คนที่จะดู" มาจาก query โดยไม่มี middleware อะไรเลย ทั้งคู่จึงตอบให้ทุกคนที่เดารหัส
8 ตัวถูก โดยไม่ต้องมี cookie

ทั้งสองเส้นต้องปิด แต่ปิดได้สองแบบ และสองแบบนี้ให้สัญญาที่ต่างกัน

| | ตัด parameter ทิ้ง อ่านจาก session | เก็บ parameter ไว้ แล้วตรวจว่าเป็นของตัวเอง |
| --- | --- | --- |
| ผู้เรียก | โกหกไม่ได้เลย | โกหกได้ แต่ได้ `403` |
| frontend | ต้องแก้ | ไม่ต้องแก้ |
| ขยายทีหลัง | ต้องเพิ่ม endpoint ใหม่เมื่ออาจารย์ต้องดูของนักศึกษา | เพิ่มสาขาที่สองใน middleware ตัวเดิม |

## สิ่งที่ต้องตัดสิน

1. id ของ "คนที่จะดู" มาจากไหน — session หรือคำขอที่ถูกตรวจ
2. ถ้าคำตอบไม่เหมือนกันทั้งสองเส้น อะไรคือสิ่งที่ตัดสินว่าเส้นไหนได้แบบไหน
3. `id` ที่ไม่ตรงกับใครเลย ต่างจาก `id` ของคนอื่นไหม

## การตัดสิน

> **ตามเพื่อนบ้านของแต่ละเส้น ไม่ใช่ตามกฎเดียวทั้งระบบ** — เส้นที่อยู่ในกลุ่มซึ่ง
> อ่านจาก session อยู่แล้ว ให้อ่านจาก session เส้นที่อยู่ในกลุ่มซึ่งรับ id จาก
> คำขอแล้วตรวจความเป็นเจ้าของ ให้ทำแบบนั้น

เหตุผลคือความสม่ำเสมอที่คนอ่านโค้ดสัมผัสได้จริงคือความสม่ำเสมอ**ภายใน router ที่
กำลังอ่านอยู่** ไม่ใช่กฎที่ประกาศไว้ในเอกสาร การบังคับให้ทั้งระบบเป็นแบบเดียวกัน
จะทำให้ทุก router มีเส้นที่ทำไม่เหมือนเพื่อนบ้านอย่างน้อยหนึ่งเส้นเสมอ

### 1. `GET /user` — เก็บ `id` ไว้ใน query แล้ว `requireSelf`

`user.route.ts` มีสองเส้น อีกเส้นคือ `GET /user/student` ที่อ่าน id จาก session
แต่กลุ่มที่ `GET /user` เหมือนจริง ๆ คือกลุ่ม `portfolio` ทั้งสิบ router ของ #31
ซึ่งรับ `user_id` จากคำขอแล้วให้ `requireSelf` ปฏิเสธของคนอื่นด้วย `403` — และ
ADR-0001 เขียนไว้ตรง ๆ ว่าเมื่อกฎ "อาจารย์ที่สอนนักศึกษาคนนี้" มีขึ้นจริง ให้เพิ่ม
เป็นสาขาที่สองใน `requireSelf` จุดเดียว ไม่ต้องไล่แก้ router

ใช้ `requireUser` ไม่ใช่ `requireRole` — แถวใน `users` เป็นของทุกคนที่ล็อกอินได้
และการอ่านของตัวเองไม่ใช่สิทธิพิเศษของบทบาทไหน

`requireSelf` รับชื่อฟิลด์เป็นพารามิเตอร์ตัวที่สอง โดย default เป็น `user_id` ตาม
ที่กลุ่ม `portfolio` สะกด `GET /user` สะกดว่า `id` และเป็นเส้นเดียวที่สะกดแบบนั้น
— การเปลี่ยนชื่อ query parameter ที่ใช้งานอยู่จริงเพื่อประหยัดอาร์กิวเมนต์หนึ่งตัว
คือค่าใช้จ่ายที่ผู้เรียกจ่าย แต่ไม่มีใครได้อ่าน

### 2. `GET /student/enrolled/subjects` — ตัด `student_id` ทิ้ง

`student.route.ts` มีเส้นที่เป็น "เรื่องของฉัน" อยู่สี่เส้นก่อนหน้านี้
(`/course/list`, `/classwork/list`, `/all/classwork/list`, ปฏิทิน) ทุกเส้นอ่าน
นักศึกษาจาก session ตาม ADR-0003 เส้นนี้เป็นเส้นที่ห้า และไม่มีหน้าจอไหนเรียกมัน
เพื่อดูของคนอื่น — ผู้เรียกเดียวคือ form สร้างผลงานใน e-Portfolio ของเจ้าของเอง

`enrolledSubjectsQuery` จึงถูกลบทั้งตัว `400` ที่ #20 ใส่ไว้หายไปด้วย เพราะไม่มี
อะไรให้ตรวจแล้ว — ซึ่งเป็นผลลัพธ์ที่ดีกว่า: input ที่ดีที่สุดคือ input ที่ไม่มี

### 3. id ที่ไม่ตรงกับใครเลย ตอบเหมือน id ของคนอื่น

`GET /user` เคยตอบ `200` พร้อม `data: null` ตอนนี้ตอบ `403` เท่ากัน การแยก "ไม่มี
แถวนี้" ออกจาก "ไม่ใช่แถวของคุณ" คือการบอกว่ารหัส 8 ตัวไหนมีอยู่จริง ซึ่งเป็น
คำถามที่ endpoint นี้เคยตอบให้ฟรี ๆ และเป็นเหตุผลที่ต้องปิดตั้งแต่แรก

เป็นกฎเดียวกับที่ `NOT_OWNER` ถูกเขียนให้เป็นประโยคเดียวกันทั้ง "ไม่ใช่รายการของคุณ"
และ "ไม่มีรายการนี้" มาตั้งแต่ ADR-0001

## ขอบเขต

- **ไม่ได้ปิดอีกสามเส้นใน `/student`** (`/list`, `/activities/list`,
  `/activities/details/:id`) — ต้องตัดสินนโยบายเพิ่มก่อน ทั้งเรื่องอาจารย์เจ้าของ
  section และเรื่องว่า portfolio สาธารณะเข้าถึงอะไรได้บ้าง เป็น #41
- **ไม่ได้เพิ่มกฎ "อาจารย์ดูของนักศึกษาที่ตัวเองสอน"** — ยังเป็นข้อค้างเดียวกับที่
  ADR-0001 และ #30 เขียนไว้ ไฟล์นี้แค่วางเส้นเพิ่มอีกเส้นไว้ในที่ที่กฎนั้นจะลงได้

## ผลที่ตามมา

- `requireSelf` รับชื่อฟิลด์เป็นอาร์กิวเมนต์ตัวที่สอง ชนิดเป็น `"user_id" | "id"`
  ไม่ใช่ `string` — สองค่านี้คือทั้งหมดที่มีอยู่จริง ค่าที่สามต้องเป็นการตัดสินใจ
  ไม่ใช่การพิมพ์ผิดที่หลุดผ่านไปได้ router อีก 56 เส้นของกลุ่ม `portfolio` ไม่ต้อง
  แก้อะไรเลยเพราะ default ยังเป็น `user_id`
- `getEnrolledSubjects()` ฝั่ง web เลิกรับพารามิเตอร์ และ `useEffect` ที่เรียกมัน
  ไม่มี dependency แล้ว — ไม่มีอะไรใน effect นั้นที่การเปลี่ยน `studentId` จะทำให้เก่า
- จำนวนเส้นใน `/student` ที่ "เป็นเรื่องของฉัน" เพิ่มจากสี่เป็นห้า และเหลือสามเส้นที่
  รับ id จากคำขอโดยไม่มีอะไรตรวจ ซึ่งเป็นทั้งหมดของ #41 — comment หัวไฟล์ของ
  `student.schema.ts`, `student.route.ts` และ `student.test.ts` นับเลขนี้ตรงกัน
- `GET /user` ไม่มีทางตอบ `data: null` ได้อีก เพราะ `requireUser` ยืนยันว่าแถวของ
  session มีอยู่จริง และ `requireSelf` ยอมให้ผ่านเฉพาะ id นั้น

## จะกลับมาทบทวนเมื่อไหร่

เมื่อมีหน้าจอที่อาจารย์ต้องเปิดข้อมูลของนักศึกษา ตอนนั้น `GET /user` ขยายได้ที่
`requireSelf` ส่วน `GET /student/enrolled/subjects` ขยายไม่ได้ — ต้องมี endpoint
ใหม่ที่รับ `student_id` พร้อมกฎความเป็นเจ้าของของมันเอง ซึ่งเป็นราคาที่ข้อ 2 ยอมจ่าย
โดยรู้ตัว
