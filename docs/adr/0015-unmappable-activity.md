# ADR-0015 — กิจกรรมที่ยังผูกกับ CLO ไม่ได้ ตอบสามคำตอบ ไม่ใช่ `500` เดียว

- **สถานะ**: ตัดสินแล้ว 11 สิงหาคม 2569
- **ที่มา**: [issue #43](https://github.com/khthana/Deep-Portfolio/issues/43)
- **เกี่ยวข้อง**: [ADR-0012](0012-missing-row-status.md) (แถวที่ไม่มีอยู่ตอบ `404`
  — และหัวข้อ "ขอบเขต" ของไฟล์นั้นตั้งเงื่อนไขที่ไฟล์นี้มาทำให้ครบ แม้จะไม่ได้เขียน
  ลิงก์มาข้างหน้า), [ADR-0009](0009-submission-ownership.md) ข้อ 1 (เส้นแบ่ง `400`
  กับ `403`)

## บริบท

`createActivityCLOMapping()` ใน `activity-clo-mapping.service.ts` มีทางออกที่จบเป็น
`500` อยู่สามทาง และทั้งสามทางไม่มีอะไรพังเลย

| กรณี | โค้ดเดิม | สิ่งที่ผู้เรียกเห็น |
| --- | --- | --- |
| กิจกรรมไม่มีอยู่ | `throw new Error("Activity not found")` | `500` `เกิดข้อผิดพลาดภายในระบบ` |
| กิจกรรมไม่มีคะแนน | `throw` ตัวเดียวกัน | `500` ประโยคเดียวกัน |
| กิจกรรมไม่มีหมวดคะแนน | `score_ratio_id: activity?.score_ratio_id ?? 0` | `500` ประโยคเดียวกัน |

สองกรณีแรกใช้ `throw` ตัวเดียวกัน ทั้งที่เป็นคนละข่าว ส่วนกรณีที่สามไม่ได้ `throw`
เลย — มันเขียน `0` ลงคอลัมน์ที่มี foreign key ไปหา `subject_score_ratio` แล้วปล่อย
ให้ Postgres ปฏิเสธ `0` ไม่ใช่ค่าที่หมายถึง "ยังไม่มี" มันคือ id ที่ไม่มีแถวไหน
เป็นเจ้าของ

ADR-0012 เขียนไว้ในหัวข้อขอบเขตว่า `Activity not found` ยังเป็น `500` ต่อไป เพราะ
"ถูกโยนทั้งตอนที่กิจกรรมไม่มีอยู่ และตอนที่กิจกรรมมีอยู่แต่ไม่มีคะแนน การให้สถานะ
กับมันจึงต้องแยกสองกรณีออกจากกันก่อน" ไฟล์นี้คือการแยกนั้น

## สิ่งที่ต้องตัดสิน

1. `?? 0` ควรกลายเป็นอะไร — ปฏิเสธ หรือเขียน `null`
2. กิจกรรมที่ไม่มีอยู่ตอบ `404` หรือ `400` ในเมื่อ `activity_id` มาจาก body
3. ถ้ากิจกรรมขาดทั้งหมวดคะแนนและคะแนน ผู้เรียกอ่านประโยคไหน

## การตัดสิน

> **สามกรณีแยกออกจากกัน ได้สถานะและประโยคของตัวเองคนละอัน และถูกถามก่อนเขียน
> ไม่ใช่ดักหลังจากฐานข้อมูลปฏิเสธ**

```ts
if (!activity) throw NOT_FOUND();
if (!activity.score_ratio_id) throw NO_SCORE_CATEGORY();
if (!activity.score_number) throw NO_SCORE();
```

### 1. ปฏิเสธ ไม่ใช่เขียน `null`

`activity_clo_mapping.score_ratio_id` เป็น `Int` ไม่ใช่ `Int?` การเขียน `null`
ลงไปจึงต้องแก้ schema และเพิ่ม migration ก่อน และ issue เองก็ตั้งเงื่อนไขไว้แล้วว่า
ทางนั้นต้องตอบให้ได้ว่า**ใครเป็นคนตามมาเติมค่าให้** คำตอบคือไม่มีใคร ไม่มี endpoint
ไหนไล่เติม `score_ratio_id` ให้ mapping ที่ค้างอยู่ แถวที่เขียนไว้เป็น `null` จึงจะ
ค้างเป็น `null` ตลอดไป และกลายเป็นแถวที่คิดคะแนนไม่ได้ซึ่งไม่มีใครเห็น

การปฏิเสธตรงกว่า: กิจกรรมที่ยังไม่ได้จัดหมวดคะแนนยังไม่พร้อมจะถูกผูกกับ CLO
เพราะน้ำหนักที่ mapping เก็บไว้เป็นน้ำหนัก**ภายในหมวด**

**ปฏิเสธด้วย `400` และไฟล์นี้เป็นเจ้าของการตัดสินนั้นเอง** ไม่ได้อ้าง ADR-0009
เพราะ ADR-0009 ข้อ 1 วางเส้นระหว่าง `403` กับ `400` ในเรื่อง**ความเป็นเจ้าของ** และ
เหตุผลของมัน ("เลขที่ส่งมาถูกต้องทุกประการ") ถ้าอ่านตรง ๆ จะชี้ออกจาก `400` ด้วยซ้ำ
สถานการณ์ที่นี่ไม่ตรงกับสามหมวดที่โปรเจกต์มีอยู่เลย — ไม่ใช่สิทธิ์ที่ถูกปฏิเสธ (`403`)
ไม่ใช่แถวที่ไม่มีอยู่ (`404`) และไม่ใช่ค่าใน body ที่ผิดรูป (`400` แบบ #20) มันคือ
คำขอที่ถูกต้องซึ่งสวนกับสถานะของแถวที่มันอ้างถึง

`409` หรือ `422` จะตรงกว่าตามตัวอักษรของ HTTP แต่ทั้งระบบไม่มีทั้งสองรหัสอยู่เลย —
`HttpError` ถูกสร้างด้วย `400`, `401`, `403`, `404` เท่านั้น (32 จุด) การเพิ่มรหัสที่
ห้าเพื่อกรณีเดียวจะทำให้ frontend ต้องรู้จักรหัสที่ไม่เคยเจอ ในเมื่อสิ่งที่ frontend
ต้องทำเหมือนกันทุกกรณีคือแสดงประโยคที่ API ส่งมา `400` จึงเป็นคำตอบที่พอดี และประโยค
ต่างหากที่แบกความหมาย

### 2. กิจกรรมที่ไม่มีอยู่ตอบ `404`

ADR-0012 ข้อ 2 วางเส้นไว้ว่าแถวที่ผู้เรียก**อ้างถึง**ตอบ `404` ส่วน**ค่าที่ผู้เรียก
ส่งมา**ตอบ `400` เส้นนั้นวางไว้กับ `PUT /activity/:id` ที่ตัวกิจกรรมมาจาก path

ที่นี่ `activity_id` มาจาก body แต่บทบาทของมันยังเป็นอย่างเดิม — กิจกรรมคือสิ่งที่
คำขอนี้พูดถึง mapping ถูกเพิ่มเข้าไปในตัวมัน ส่วน `clo_id` คือค่าที่ mapping ชี้
ออกไป เส้นแบ่งของ ADR-0012 เป็นเรื่องของ**บทบาท** ไม่ใช่ของตำแหน่งในคำขอ กิจกรรมจึง
ได้ `404` `ไม่พบกิจกรรมที่ต้องการ` ซึ่งเป็นประโยคเดียวกับที่ `portfolio-activity`
ใช้อยู่แล้ว

`clo_id` ที่ไม่ตรงกับ CLO ไหนยังเขียนผ่านเหมือนเดิม เพราะตารางนี้ไม่มี foreign key
บน `clo_id` — เป็นเรื่องของ schema และอยู่นอก #43

### 3. ถามหมวดคะแนนก่อนคะแนน

กิจกรรมขาดได้ทั้งสองอย่างพร้อมกัน คำตอบที่ผู้เรียกได้จึงต้องเลือกมาหนึ่งประโยค
หมวดคะแนนถูกถามก่อน เพราะเป็นค่าที่ mapping **ต้องใช้เขียนคอลัมน์ของตัวเอง** ส่วน
คะแนนเป็นแค่ตัวตั้งของการคำนวณว่า mapping นั้นมีค่าเท่าไหร่ อย่างแรกเป็นเงื่อนไข
ของการมีอยู่ อย่างหลังเป็นเงื่อนไขของการมีความหมาย

มี test ยืนบนลำดับนี้โดยตรง (`names the missing category first when both are
missing`) เพื่อให้การสลับลำดับในอนาคตเป็นการตัดสินใจ ไม่ใช่ผลข้างเคียง

### ประโยคที่ผู้เรียกอ่าน

| กรณี | สถานะ | ประโยค |
| --- | --- | --- |
| กิจกรรมไม่มีอยู่ | `404` | `ไม่พบกิจกรรมที่ต้องการ` |
| ไม่มีหมวดคะแนน | `400` | `กิจกรรมนี้ยังไม่ได้เลือกประเภทสัดส่วนคะแนน` |
| ไม่มีคะแนน | `400` | `กิจกรรมนี้ยังไม่มีคะแนนให้แบ่งตามผลการเรียนรู้` |

คำว่า "ประเภทสัดส่วนคะแนน" กับ "ผลการเรียนรู้" เป็นคำที่หน้าจอใช้อยู่แล้ว
(`activity-detail-form.tsx`, `clo-section.tsx`) ไม่ได้ตั้งคำใหม่

**คะแนน `0` นับว่าไม่มีคะแนน** — `activities.score_number` เป็น `Int?` ที่
`@default(0)` กิจกรรมที่ยังไม่มีใครใส่คะแนนจึงมาถึงที่นี่เป็น `0` ไม่ใช่ `null`
ทั้งสองค่าไม่มีอะไรให้แบ่ง จึงใช้ประโยคเดียวกัน นี่คือพฤติกรรมเดิม ไม่ได้เปลี่ยน
เปลี่ยนแต่สถานะกับประโยค

## ขอบเขต

- **ไม่ได้แตะ `?? 0` อีกสามจุด** — `activity.service.ts:518` และ
  `student-activity.service.ts:295,380` ใช้ `score_ratio_id ?? 0` ใน `where` ของ
  `findUnique` ไม่ใช่ใน `data` ตรงนั้น `0` ทำหน้าที่เป็นคีย์ที่ไม่ตรงกับแถวไหน
  ผลลัพธ์จึงเป็น `null` ซึ่งโค้ดรอบข้างรับมือไว้แล้ว (ส่ง `undefined` เข้าไปแทนจะกลาย
  เป็น validation error ของ Prisma ไม่ใช่การอ่านที่ไม่กรอง) จุดที่ #43 แก้คือจุดเดียว
  ที่ `0` ถูก **เขียน** ลงฐานข้อมูล
- **ไม่ได้แปลง `P2003` ทั้งระบบ** — ADR-0012 ข้อ 3 ยังค้างอยู่ตามเดิม สิ่งที่ทำที่นี่
  คือถามก่อนเขียนจนไม่มี `P2003` ให้เกิด ไม่ใช่การไปแก้ `errorHandler`
  `POST /mapping/learning-activity` ที่อ้าง learning activity ซึ่งไม่มีอยู่ยังเป็น
  `500` จาก `P2003` เหมือนเดิม และตอนนี้เป็น `500` ตัวเดียวที่เหลือในไฟล์ test นั้น
- **ไม่ได้ตรวจว่า CLO เป็นของ section เดียวกับกิจกรรม** — ไม่มี foreign key และ
  ไม่มีการตรวจที่ไหนมาแต่เดิม อยู่นอก #43
- **ไม่ได้ทำให้ประโยคใหม่ไปถึงหน้าจอ** — ดูหัวข้อถัดไป

## ผลที่ตามมา

- ไม่มีแถวไหนใน `activity_clo_mapping` ที่ `score_ratio_id` เป็น `0` ได้อีก และไม่
  เคยมีมาก่อนด้วย เพราะ foreign key ปฏิเสธทุกครั้ง — สิ่งที่เปลี่ยนคือคำตอบ ไม่ใช่
  ข้อมูล จึงไม่ต้อง migrate อะไร
- **ฝั่ง web ยังไม่ได้ประโยชน์จากประโยคใหม่** `mapping-section.tsx` จับ error แล้ว
  แสดง `ไม่สามารถเพิ่มกิจกรรมได้ กรุณาลองใหม่อีกครั้ง` ตายตัว และประโยคของ API หายไป
  ตั้งแต่ชั้น thunk — `createAsyncThunk` ที่ไม่ใช้ `rejectWithValue` ส่งต่อแค่
  `SerializedError` ซึ่ง `message` คือ `"Request failed with status code 400"` ของ
  axios ไม่ใช่ body ที่ API ตอบ นี่เป็นรูปแบบเดียวกันทั้ง 10 กว่า slice ในโปรเจกต์
  การแก้จึงเป็นงานข้ามระบบของตัวเอง ไม่ใช่ของ #43 — บันทึกไว้ใน
  `BEHAVIOR-CHANGES.md` และแยกเป็น issue
- `errorHandler` ยังคง `console.error` ทุก error รวมทั้ง `400` สามตัวนี้ ซึ่งทำให้
  log มีบรรทัดที่ไม่ใช่ข้อผิดพลาดของระบบปนอยู่ เป็นพฤติกรรมเดิมของทุก `HttpError`
  ไม่ได้เกิดจาก ticket นี้

## จะกลับมาทบทวนเมื่อไหร่

เมื่อมีใครตัดสินใจว่า thunk ควรส่งประโยคของ API ต่อไปให้หน้าจออย่างไร — ตอนนั้น
ประโยคทั้งสามในไฟล์นี้จะเป็นตัวทดสอบว่ารูปแบบใหม่ใช้ได้จริงหรือไม่

**ตัดสินแล้วใน [ADR-0022](0022-api-sentence-reaches-the-screen.md)** (#51,
12 สิงหาคม 2569) คำตอบคือไม่แก้ที่ thunk เลย — ประโยคถูกวางกลับลงบน
`error.message` ที่ axios interceptor ก่อนที่ Redux จะได้เห็น error นั้น และ
`mapping-section.tsx` แสดงมันแทนประโยคตายตัวของตัวเอง ประโยคทั้งสามในไฟล์นี้คือ
กรณีที่รูปแบบใหม่ถูกเขียนขึ้นมาเพื่อ
