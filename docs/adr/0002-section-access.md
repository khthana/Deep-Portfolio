# ADR-0002 — อาจารย์คนไหนเข้าถึงกลุ่มเรียนไหนได้

- **สถานะ**: ตัดสินแล้ว 10 สิงหาคม 2569
- **ที่มา**: [issue #30](https://github.com/khthana/Deep-Portfolio/issues/30)
- **เกี่ยวข้อง**: [ADR-0001](0001-portfolio-access.md) (กติกาเดียวกันในรูปของ
  เจ้าของแถว), [#12](https://github.com/khthana/Deep-Portfolio/issues/12)
  (`created_by` ของประกาศ),
  [#26](https://github.com/khthana/Deep-Portfolio/issues/26) (สาม `GET` ของกลุ่ม)

## บริบท

`GET /gradebook/per-student` กับ `GET /gradebook/per-activity` รับ `section_id`
จาก query แล้วตอบทันที #15 ทำให้ทั้งคู่ต้องเป็นอาจารย์ที่ล็อกอินแล้วก็จริง แต่
"เป็นอาจารย์" กับ "เป็นอาจารย์ของกลุ่มเรียนนี้" เป็นคนละคำถาม อาจารย์คนใดก็ได้ใน
ระบบจึงเปิดสมุดคะแนนของกลุ่มเรียนที่ตัวเองไม่ได้สอนได้ พร้อมรายชื่อนักศึกษาและคะแนน
รายกิจกรรม และ `section_id` เป็นจำนวนเต็มที่เดินไล่ทีละหมายเลขได้

เรื่องเดียวกันนี้ค้างอยู่หลายที่ — `created_by` ของ `POST /announcement` (#12) และ
สาม `GET` ของกลุ่ม (#26) — เพราะระบบยังไม่มีการตรวจความเป็นเจ้าของกลุ่มเรียนอยู่
ที่ใดเลย การแก้ทีละ endpoint จึงไม่ได้ปิดอะไรจริง

## สิ่งที่ต้องตัดสิน

ความสัมพันธ์ "อาจารย์–กลุ่มเรียน" มีนิยามที่เป็นไปได้หลายแบบ

1. **ผู้สอนกลุ่มเรียนนั้น** — มีแถวใน `course_sections_teacher`
2. **ผู้สอนรายวิชานั้น** — สอนกลุ่มเรียนใดก็ได้ของ `semester_courses` เดียวกัน
3. **คนในภาควิชาเดียวกัน** — ผ่าน `department_id` ของรายวิชา

## การตัดสิน

**แบบที่ 1 — ผู้สอนกลุ่มเรียนนั้น**

> อาจารย์กระทำการกับกลุ่มเรียนที่ตัวเองสอนเท่านั้น "สอน" คือมีแถวใน
> `course_sections_teacher` ที่ `section_id` ตรงกับที่คำขอระบุ และ `user_id` ตรงกับ
> เจ้าของ session

ไม่ผ่านแล้วได้ `403` พร้อม `{ "success": false, "message": "คุณไม่มีสิทธิ์เข้าถึงข้อมูลของกลุ่มเรียนนี้" }`

เลือกแบบที่ 1 เพราะเป็นความสัมพันธ์เดียวที่ **มีอยู่จริงในฐานข้อมูลแล้ว** เป็นแถว
เดียวที่ค้นเจอด้วย unique index `(section_id, user_id)` ที่มีอยู่ก่อนแล้ว ส่วนแบบที่
2 กับ 3 ต้องเดินผ่านตารางกลางเพิ่มโดยไม่มีใครขอ และไม่มีหน้าไหนใน `apps/web` ที่
อาจารย์เปิดข้อมูลของกลุ่มเรียนที่ตัวเองไม่ได้สอน — การเปิดไว้ก่อนแล้วมาปิดทีหลัง
แพงกว่าการปิดไว้ก่อนแล้วเปิดเพิ่ม เหมือนที่ ADR-0001 ให้เหตุผลไว้

### กลุ่มเรียนที่ไม่มีอยู่จริง ก็ตอบ `403` เหมือนกัน

ไม่ใช่ `404` และไม่ใช่ `200` ที่ว่างเปล่า `section_id` เป็นจำนวนเต็มเรียงกัน ถ้าคำตอบ
แยกได้ว่า "ไม่มีกลุ่มเรียนนี้" กับ "มีแต่ไม่ใช่ของคุณ" ผู้เรียกก็ไล่หมายเลขแล้ววาด
แผนที่การสอนของทั้งสถาบันได้จากภายนอก จุดนี้ต่างจาก ADR-0001 ที่ปล่อยแถวที่ไม่มีอยู่
จริงผ่านไปให้ controller ตอบ 404 เพราะที่นั่น id เป็น uuid ซึ่งเดาไม่ได้อยู่แล้ว

### middleware อยู่หลัง `validate` เสมอ

คำขอที่ไม่ระบุ `section_id` หรือระบุมาผิดรูป คือคำขอที่ผิดรูป `400` บอกผู้เรียกได้
มากกว่า `403` เหตุผลเดียวกับ `requireSelf` ใน ADR-0001 สำหรับ `POST /announcement`
ที่เป็น multipart ลำดับจึงเป็น `requireRole` → `upload` → `validate` →
`requireOwnSection` ซึ่งยังไม่มีไฟล์ตกค้าง เพราะ multer ของเส้นทางนี้เก็บไฟล์ไว้ใน
หน่วยความจำ ตัวที่เขียนลง MinIO คือ service ซึ่งอยู่หลังการปฏิเสธ

### `created_by` ของประกาศมาจาก session

`POST /announcement` เคยรับ `created_by` มาจาก body อาจารย์จึงโพสต์ในนามเพื่อนร่วมงาน
ได้ ฟิลด์นี้หายไปจาก schema แล้ว ใช้กติกาเดียวกับที่ ADR-0001 ใช้กับทั้งกลุ่ม
portfolio — **ผู้กระทำคือเจ้าของ session เสมอ ไม่ใช่คนที่คำขอบอกว่าเป็น**

### `all_section` แผ่ไปเฉพาะกลุ่มเรียนที่ผู้โพสต์สอน

เดิม `all_section` หาแถวใน `course_sections_teacher` ของกลุ่มเรียนที่ระบุ **โดยไม่สน
ว่าเป็นของใคร** แล้วโพสต์ลงทุกกลุ่มเรียนของรายวิชานั้น ผลคืออาจารย์ที่สอนกลุ่มเดียว
เขียนลงกระดานข่าวของเพื่อนร่วมงานได้ ถ้าปล่อยไว้ กติกาข้างบนก็ถูกข้ามด้วยคำขอเดียว
ตอนนี้ปลายทางคือกลุ่มเรียนของรายวิชานั้น **ที่ผู้โพสต์สอน** เท่านั้น

### ทำไมสาม `GET` ของกลุ่ม (#26) ไม่ได้ใช้กติกานี้

> **ปิดแล้วใน [ADR-0003](0003-enrolment-access.md)** — #26 ตัดสินว่าอ่านจาก session
> และเพิ่ม `requireEnrolledSection` ย่อหน้าข้างล่างเก็บไว้เป็นเหตุผลของตอนที่ #30
> ตัดสินใจไม่ทำ

เพราะคำถามที่ต้องตอบไม่เหมือนกัน `GET /student-activity-group/all` และ
`/without-group` ระบุกลุ่มเรียน ส่วน `GET /student-activity-group/` ระบุนักศึกษา และ
ผู้เรียกที่ควรได้คำตอบมีสองแบบ — อาจารย์ของกลุ่มเรียน (ผ่าน
`course_sections_teacher`) กับนักศึกษาที่ลงทะเบียนอยู่ (ผ่าน `student_course`)
กติกาของ ADR นี้ครอบคลุมแค่ครึ่งแรก ครึ่งหลังไม่มีที่ไหนในระบบตรวจอยู่เลย และ #26
ยังต้องตัดสินก่อนว่า `student_id` มาจาก session หรือจาก query — ซึ่งเป็นการเปลี่ยน
สัญญากับ frontend ที่ควรทำรวดเดียวทั้งสามตัว ไม่ใช่แทรกมาครึ่งหนึ่งที่นี่

## ผลที่ตามมา

- middleware `requireOwnSection` อยู่ที่ `apps/api/src/middlewares/owner.middleware.ts`
  ข้างกติกาของ ADR-0001 ใช้ซ้ำได้ทั้งแบบที่ `section_id` มาจาก query และจาก body
  รับพารามิเตอร์แค่ตำแหน่งที่จะไปอ่าน ไม่ต้องส่ง schema เข้ามา
- บังคับใช้แล้วสามที่ — `GET /gradebook/per-student`, `GET /gradebook/per-activity`
  และ `POST /announcement`
- อาจารย์ที่ไม่ได้สอนกลุ่มเรียนนั้นได้ `403` ที่เคยได้ `200` ดู
  [`BEHAVIOR-CHANGES.md`](../../BEHAVIOR-CHANGES.md)
- **ยังมี endpoint ของอาจารย์อีก 9 ตัวที่ระบุกลุ่มเรียนแต่ยังไม่ได้ตรวจ** —
  `POST`/`PUT /activity`, `POST`/`PUT /learning-activity`, `POST /lesson-plan`,
  `POST /score-weight`, `POST /course-material`, `POST /course/schedule` และ
  `POST /course/clo` ทั้งหมดใช้ middleware ตัวเดียวกันนี้ได้ทันที ไม่ได้ทำใน #30
  เพราะแต่ละตัวมี test ที่ arrange อาจารย์ไว้แบบไม่ผูกกับกลุ่มเรียน การไล่แก้ทั้งหมด
  จึงเป็นงานคนละก้อนกับการตัดสินกติกา — สิ่งที่ #30 รับผิดชอบ
- **ส่วนที่ยากกว่ายังไม่ได้ทำเลย** — endpoint ที่ระบุ **แถว** แทนกลุ่มเรียน
  (`DELETE /activity`, `PUT`/`DELETE /clo`, `PUT`/`DELETE /lesson-plan`,
  `PUT`/`DELETE /score-weight`, `DELETE /course-material`) ต้องหากลุ่มเรียนจาก id
  ของแถวก่อน ซึ่งเป็นรูปเดียวกับ `requireOwnEntry` + `entryOwner` ของ ADR-0001 คือ
  ตารางค้นเจ้าของหนึ่งชุดต่อหนึ่งตาราง
- **`GET` ของฝั่งรายวิชายังไม่มีแม้แต่ session** — `GET /announcement`,
  `GET /course`, `GET /activity/list`, `GET /lesson-plan`, `GET /score-weight`,
  `GET /course-material` เรียกได้โดยไม่ต้องล็อกอิน เป็นช่องที่กว้างกว่าเรื่องความ
  เป็นเจ้าของ และไม่ได้อยู่ในเกณฑ์ยอมรับของ #30

## จะกลับมาทบทวนเมื่อไหร่

เมื่อมีบทบาทที่ต้องอ่านข้ามกลุ่มเรียนจริง ๆ — หัวหน้าภาค ฝ่ายทะเบียน หรือผู้ช่วยสอน
ที่ไม่ได้อยู่ใน `course_sections_teacher` — ให้เพิ่มเป็นสาขาที่สองใน
`requireOwnSection` จุดเดียว ไม่ต้องไล่แก้ router

ส่วนกติกาของฝั่งนักศึกษา #26 ตัดสินแล้วและอยู่ที่
[ADR-0003](0003-enrolment-access.md) คำถาม "ใครอยู่ในกลุ่มเรียนนี้" จึงมีคำตอบครบ
ทั้งสองด้านแล้ว middleware ทั้งสองตัวอยู่ในไฟล์เดียวกันและสร้างจากตัวช่วยตัวเดียวกัน
