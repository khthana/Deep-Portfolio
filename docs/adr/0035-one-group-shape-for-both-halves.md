# ADR-0035 — สองครึ่งที่ตอบรูปเดียวกันเป๊ะ ใช้ประกาศชุดเดียว

- **สถานะ**: ตัดสินแล้ว 19 สิงหาคม 2569
- **ที่มา**: [issue #68](https://github.com/khthana/Deep-Portfolio/issues/68)
  รอบ group
- **เกี่ยวข้อง**: [ADR-0029](0029-api-types-per-feature.md) กติกาของแต่ละรอบ
  (ใบนี้ใช้ข้อ 1, 2, 3 และ 4), [ADR-0034](0034-submissions-move-as-a-pair.md)
  รอบก่อนหน้า ซึ่งเป็นรอบที่ย้าย `MemberStatus` กับ `SubmissionGroup` เข้า
  `group.ts` ไว้ก่อนแล้ว ใบนี้ไม่ได้ทบทวนข้อไหนของสองใบนั้น

## บริบท

รอบที่แล้วย้ายครึ่งบนของ `group.ts` ไปแล้ว — รูปกลุ่มที่**อาจารย์**เห็นบนตาราง
ตรวจงาน รอบนี้คือครึ่งล่าง: รูปกลุ่มที่**นักศึกษา**เห็นบนหน้างานของตัวเอง ซึ่ง
เป็นคนละคำถามกัน (ใครอยู่ในกลุ่มฉัน และใครยังไม่ตอบรับ ไม่ใช่ คะแนนนี้ลงที่ใคร)

หกเส้นต่อครึ่ง สิบสองเส้นรวม — สิบเส้นในนั้นมีรูปให้ย้าย:

| เส้น                                          | ตอบ                       |
| --------------------------------------------- | ------------------------- |
| `GET /student-activity-group`                 | `GroupDetailResp \| null` |
| `GET /student-activity-group/all`             | `GroupDetailResp[]`       |
| `GET /student-activity-group/without-group`   | `StudentWithoutGroup[]`   |
| `POST /student-activity-group`                | `GroupIdResp`             |
| `PATCH /student-activity-group`               | `GroupIdResp`             |
| `DELETE /student-activity-group/:group_id`    | `null` — ไม่มีรูปให้ย้าย  |

ฝาแฝดของทั้งหมดอยู่ใต้ `/student-learning-activity-group` และตอบรูปเดียวกัน
ทุกฟิลด์

บวกอีกเส้นที่ไม่ได้อยู่ใต้ route ไหนในสองนั้น แต่เป็นของ feature นี้แน่นอน คือ
`POST /group/validate-invite` — เส้นที่หน้าเชิญเข้ากลุ่มถามก่อนจะแสดงปุ่ม
(ส่วน `POST …/resend-invite` ตอบ `null` ใน `data` เหมือน `DELETE`)

ก่อนรอบนี้ ฝั่ง API ประกาศรูปตอบ**สองชุด** ไฟล์ละชุด
(`student-activity-group.model.ts` กับ `student-learning-activity-group.model.ts`)
โดยไฟล์หลังยัง `import { GroupRole } from "./student-activity-group.model"`
มาใช้ — คือใช้ร่วมบางตัว ประกาศซ้ำบางตัว ส่วนฝั่ง web ประกาศ**ชุดเดียว** แล้วให้
ทั้งสองครึ่งอ่านตัวเดียวกันมาตลอด

## สิ่งที่ประกาศเดิมปิดไว้

| จุด                                  | type เดิมบอก                              | ของจริง                                                 |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------------- |
| `full_name_th` (เส้น without-group)  | `string` ทั้งสองฝั่ง                      | คอลัมน์เป็น `String?` และ service ส่งต่อดิบ ๆ           |
| `status` (เส้น validate-invite)      | ฝั่ง web เขียน `"ACCEPTED"`               | คอลัมน์กับ API ส่ง `"ACCEPT"` — ไม่มี `ACCEPTED` ที่ไหน |
| `role` (สองเมธอด `…InSec`)           | `as GroupRole` ทับผลของ Prisma            | enum ของ Prisma เป็น `LEADER \| MEMBER` ตรงกันอยู่แล้ว  |
| `studentList` (slice ฝั่ง web)       | `StudentDetailResp[]` — optional ทุกฟิลด์ | มีแต่แถว without-group เท่านั้นที่เคยเขียนลงไป          |
| `studentOptions` (slice ฝั่ง web)    | ประกาศไว้เป็น field ของ state             | ไม่มี reducer ไหนเขียน ไม่มีหน้าจอไหนอ่าน               |

`"ACCEPTED"` ซ่อนอยู่ได้สองชั้น: thunk เขียน `ResponseWrapper<any>` ทับไว้อีกที
ค่าจึงไปถึงหน้าจอในรูป `any` และ `accept-invite-page.tsx` ก็เทียบกับ `"ACCEPT"`
ของมันเองถูกมาตลอด ประกาศที่ผิดจึงไม่เคยทำให้อะไรพัง — มันแค่ไม่จริง

## การตัดสินใจ

**1. รูปเดียวกันเป๊ะ ใช้ประกาศชุดเดียว ไม่แยกตามครึ่ง**

รอบที่แล้ว (ADR-0034) ย้ายสอง feature พร้อมกันแต่ให้**ไฟล์คนละไฟล์** เพราะสอง
ครึ่งนั้นตอบไม่เหมือนกันจริง ๆ — ครึ่งกิจกรรมประเมินมีคะแนน ครึ่งการเรียนรู้ไม่มี
รอบนี้ต่างออกไป: ทุกเส้นข้างบนกับฝาแฝดของมันตอบเหมือนกัน**ทุกฟิลด์** ต่างกันแค่
ตารางที่อ่าน จึงได้ `GroupDetailResp`, `GroupMemberDetail`, `StudentWithoutGroup`
และ `GroupIdResp` อย่างละตัว ไม่ใช่อย่างละสองตัว

ทางเลือกที่ไม่เอาคือทำ `LearningActivityGroupDetailResp` ให้ครบคู่ตามชื่อ route
ซึ่งจะได้ประกาศที่เหมือนกันเป๊ะสองชุดใน package — คือย้ายปัญหาที่ #61 มาแก้ไปไว้
ที่ใหม่ ฝั่ง web พิสูจน์มาแล้วว่าชุดเดียวพอ เพราะมันใช้ชุดเดียวมาตั้งแต่ต้นและ
ไม่เคยเป็นปัญหา ที่ยุบลงจึงเป็นสำเนาฝั่ง API ไม่ใช่ของฝั่ง web

**สิ่งที่ยังแยก**คือ `MemberDetail` (request body ของเส้น `POST`/`PATCH`) ซึ่ง
ADR-0028 กันออกนอกขอบเขตตั้งแต่ต้น — มันยังอยู่ที่ schema ฝั่ง API และ
`course-type.ts` ฝั่ง web เหมือนเดิม

ทั้งสามตัวอยู่ใน `group.ts` รวมทั้ง `StudentWithoutGroup` ที่หน้าตาเป็นแถวของ
นักศึกษา และมี `student.ts` ให้เลือกอยู่แล้วตั้งแต่รอบที่แล้ว ที่ไม่ไปอยู่ตรงนั้น
เพราะ ADR-0029 ข้อ 2 ให้ดูว่ารูปนั้น**เป็นของ**ใคร ไม่ใช่ว่ามันมีฟิลด์ของใคร —
"นักศึกษาที่ยังไม่ถูกจัดกลุ่ม" เป็นคำถามของ feature group ล้วน ๆ ตอบโดย endpoint
ของ group และไม่มีความหมายนอกจอสร้างกลุ่ม ต่างจาก `StudentNameBrief` ใน
`student.ts` ที่เป็นชื่อของนักศึกษาเฉย ๆ ซึ่งเส้นไหนก็หยิบไปแปะได้

**2. ชื่อบอกรูป ไม่ใช่บอกเส้น**

ชื่อเดิมทั้งสามบอกว่า "ใครไปเอามา": `GetStudentActivityGroupResp`,
`MemberDetailResp`, `GetStudentsWithoutGroupResp` พอเส้นที่ตอบรูปเดียวกันมีหก
เส้น ชื่อแบบนั้นจะเลือกไม่ถูกว่าตั้งตามเส้นไหน ชื่อใหม่จึงบอกว่ามัน**เป็น**อะไร
ตาม ADR-0029 ข้อ 1 ที่ให้เลี่ยงชื่อที่จะไปชนกันภายหลัง — `GroupDetailResp` คือ
กลุ่มหนึ่งกลุ่ม `GroupMemberDetail` คือสมาชิกหนึ่งคน `StudentWithoutGroup` คือ
เพื่อนร่วมห้องที่ยังไม่ถูกจัดกลุ่ม

**3. `full_name_th` เขียนว่า `string | null` ตามคอลัมน์**

`student.full_name_th` เป็น `String?` ที่ default มาจากชื่อกับนามสกุลรวมกัน
(`dbgenerated`) เส้น without-group `select` มันออกมาแล้วส่งต่อโดยไม่แตะ — ไม่มี
`|| ""` เหมือนที่ `GroupMemberDetail.student_name` มี ประกาศเดิมฝั่ง API เขียนว่า
`string` แล้วปิดด้วย `as GetStudentsWithoutGroupResp[]` ทั้งก้อน รอบนี้ตัด `as`
ออกทั้งสองไฟล์ แล้วผลของ `select` ก็ผ่านโดยไม่ต้องแปลงอะไร ซึ่งเป็นคำยืนยันว่า
ประกาศใหม่ตรงกับสิ่งที่ Prisma คืนมาจริง

**สายส่งไม่เปลี่ยนสักไบต์** ที่เปลี่ยนคือประโยคที่เขียนไว้ว่ามันเป็นอะไร แต่
ประโยคที่ถูกต้องทำให้เห็นจุดที่อ่านมันโดยไม่กันไว้: ฝั่ง web อ่านค่านี้สี่จุดใน
สอง component สองจุดเขียน `?? ""` ไว้อยู่แล้ว อีกสองจุดยัดลง template ตรง ๆ ใน
`label` ของตัวเลือกสมาชิก ซึ่งถ้าเป็น null จริงจะขึ้นคำว่า `null` ให้นักศึกษาอ่าน
รอบนี้เติม `?? ""` ให้สองจุดนั้นด้วย ไม่ใช่การเปลี่ยนสิ่งที่ API ตอบ จึงไม่มี
รายการใน `BEHAVIOR-CHANGES.md` — เป็นการปิดช่องที่ประกาศเดิมบังไว้

**4. เส้นเขียนทั้งสี่ย้ายด้วย เส้นลบไม่ย้าย**

`POST` กับ `PATCH` ของทั้งสอง route ตอบ `{ group_id }` ซึ่งฝั่ง web เขียนเป็น
literal ซ้ำอยู่แปดจุด และเมธอดฝั่ง API ทั้งสี่ไม่มี return type เขียนไว้เลย รอบนี้
จึงได้ `GroupIdResp` ตามขอบเขตของ ADR-0028 ที่เป็น "สิ่งที่ API ตอบ" ไม่ได้แยกตาม
method — เหมือนที่ ADR-0034 ย้าย `GradeStudentActivityResp` ของเส้น `POST` มาแล้ว

เคสฝั่ง `PATCH` ปัก `toEqual({ group_id })` ไว้ครบอยู่แล้วทั้งสองครึ่ง ส่วนเคส
`POST` ยืนยันแค่ `data.group_id` รอบนี้จึงขยายให้ไล่ชื่อทุกคีย์เหมือนกัน

`DELETE` ไม่ย้าย เพราะ controller ส่ง `null` เข้า `data` — ไม่มีรูปให้ประกาศ

**5. `ValidateInviteResp` ย้ายมาด้วย แต่ `accept-invite` ไม่**

`POST /group/validate-invite` ตอบ `{ status }` ซึ่งเป็น `MemberStatus` ที่อยู่ใน
`group.ts` อยู่แล้ว มีเคสปักชื่อคีย์ไว้ครบใน `group-invite.test.ts` มาตั้งแต่ก่อน
รอบนี้ (`toEqual({ status: "PENDING" })`) จึงไม่ต้องเขียนเคสใหม่ และการผูก type
นี้เข้าไปทำให้ `"ACCEPTED"` ที่ผิดหายไปพร้อม `any` หนึ่งตัวในกอง #63

`POST /group/accept-invite` **ไม่**ย้าย และไม่ใช่การลืม: มันตอบ
`{ success, message }` โดยไม่มีคีย์ `data` เลย สิ่งที่ผู้เรียกจะ import คือ
"ไม่มี body" ซึ่งเป็นคำถามเรื่อง envelope ไม่ใช่เรื่องรูปของ feature — และ
envelope เป็นของ #67 `any` ตัวที่เหลืออยู่ตรงนั้นจึงยังอยู่

**6. slice ฝั่ง web ตามมาในรอบเดียวกัน ตาม ADR-0029 ข้อ 4**

`studentList` ใน `course-slice.ts` เขียนว่า `StudentDetailResp[]` ซึ่งทุกฟิลด์
เป็น optional — จึงรับอะไรก็ได้ และรับแถว without-group มาตลอดโดยไม่มีใครทัก
reducer ที่เขียนลง field นี้มีสองตัว และทั้งสองคือ thunk ของเส้น without-group
ไม่มีตัวที่สาม รอบนี้จึงเขียนตามความจริงว่า `StudentWithoutGroup[]`

ผลที่ตามมาทันทีคือ `?? ""` และ `?? 0` ที่คร่อม `student_id` อยู่สี่จุดในสอง
component กลายเป็นโค้ดที่เข้าไม่ถึง (`student_id` เป็น `string` เสมอ) จึงตัดออก
ส่วน `?? ""` ที่คร่อม `full_name_th` ยังอยู่ครบ เพราะข้อ 3 บอกว่ามันเป็น null
ได้จริง

`studentOptions` ซึ่งประกาศไว้เป็น field ของ state และ init เป็น `[]` ถูกลบทิ้ง
ไม่มี reducer เขียน ไม่มีหน้าจออ่าน — มันเป็นที่ที่ควรจะเก็บรายชื่อนี้ แต่คนเขียน
เก็บลง `studentList` แทนแล้วไม่ได้ลบตัวเดิม การเก็บไว้แปลว่าเก็บ field ที่พูดว่า
ตัวเองถือรายชื่ออยู่ ทั้งที่ไม่เคยถือ

**7. `as GroupRole` ในสองเมธอด `…InSec` ตัดออก**

Prisma ประกาศ `student_activity_group_member_role` เป็น `LEADER | MEMBER` ตรงกับ
`GroupRole` ทุกตัวอักษร cast จึงไม่ได้แปลงอะไร มันแค่ปิดตาคอมไพเลอร์ไว้เผื่อวัน
ที่ enum สองฝั่งไม่ตรงกัน — ซึ่งเป็นวันที่เราอยากรู้ที่สุด typecheck ผ่านหลังตัด
ออก คือคำยืนยันว่าตอนนี้ตรงกันจริง เมธอดคู่แฝดอีกสองตัวไม่เคยมี cast อยู่แล้ว

**8. ตารางค่า runtime ของสถานะสมาชิกยังอยู่ฝั่ง web**

`memberStatus` (const), `memberStatusLabel`, `memberStatusBGColor` และ
`memberStatusTextColor` ใน `course-type.ts` ไม่ได้ย้ายและจะไม่ย้าย — เพราะ package
นี้ไม่มี build step ได้ก็ด้วยเหตุผลว่าข้างในเป็น type ล้วนซึ่งถูกลบทิ้งตอนคอมไพล์
(ADR-0028 ข้อ 4) ใส่ `const` เข้าไปเมื่อไรข้อนั้นก็พังทันที และคำแปลภาษาไทยกับ
รหัสสีก็เป็นเรื่องของหน้าจอ ไม่ใช่สิ่งที่ API ตอบ ซึ่งเป็นขอบเขตที่ ADR-0028 วางไว้
ใต้หัวข้อ "ขอบเขต: เก็บเฉพาะ response" `MemberStatus` ฝั่ง web ที่เขียนว่า `keyof typeof memberStatus` จึงยังอยู่
และบังเอิญตรงกับ `MemberStatus` ใน package พอดี ซึ่งเป็นสถานการณ์เดียวกับที่
ADR-0031 เจอกับ `AttachmentType`

## ผลที่ตามมา

- เหลือสำเนาฝั่ง web 35 ไฟล์ 1,851 บรรทัด (จาก 35 ไฟล์ 1,858 หลังรอบส่งงาน ซึ่ง
  เป็นรอบของ ADR-0034) ไม่มีไฟล์ไหนว่างลงในรอบนี้ — `course-type.ts` ยังถือ request
  body, ตารางค่า runtime และ mapper สองตัวอยู่ครบ
- API เพิ่มสองเคส ครึ่งละหนึ่ง ทั้งคู่ไล่ชื่อทุกคีย์ของ `…/all` ซึ่งเป็นเส้นเดียว
  ในสามเส้นอ่านที่ยังไม่เคยถูกปักรูปทั้งแถว (เส้น without-group มี `toEqual` ครบ
  อยู่แล้ว ส่วนเส้นเดี่ยวปัก `members` ไว้ครบทุกฟิลด์) และแก้เคส `POST` เดิมของ
  ทั้งสองครึ่งให้ `toEqual` ทั้งวัตถุแทนที่จะดูแค่ `data.group_id` รวมเป็น 1,070
  เคสตามที่ `npm test` รายงาน — การนับ `it(` ในไฟล์จะได้ 1,068 เพราะ
  `auth.test.ts` ประกาศ `it(` ตัวหนึ่งไว้ในลูปสามรอบ
- ฝั่ง web ไม่เพิ่มไม่ลดเคส (448) — สิ่งที่แก้คือ fixture สองตัวที่เคยเขียน
  `as unknown as` เปลี่ยนเป็น `satisfies StudentWithoutGroup[]` เพราะตอนนี้มัน
  ตรงรูปจริงแล้ว จึงไม่ต้องหลอกคอมไพเลอร์อีก
- `npm run lint` เหลือ 216 warning (จาก 217) — `any` ฝั่ง web เหลือ 140 ตัว
- **ไฟล์ model ฝั่ง API ทั้งสองไฟล์ไม่ได้ถูกลบ** ต่างจากที่ ADR-0029 ข้อ 3 ทำกับ
  `gradebook.model.ts` เพราะทั้งสองยังไม่ว่าง — ยัง re-export request body จาก
  schema อยู่ ที่เหลือไว้จึงไม่ใช่ shim ของสิ่งที่ย้ายไป แต่เป็นสิ่งที่ไม่ได้ย้าย
- `apps/web/src/types/group-type.type.ts` ยังอยู่ และไม่มีอะไรให้ย้าย — ในนั้นมี
  แต่ `AcceptInviteBody` กับ `ValidateInvite` ซึ่งเป็น request body ทั้งคู่
