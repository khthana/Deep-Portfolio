# ADR-0029 — กติกาของการย้าย type ทีละ feature เข้า package กลาง

- **สถานะ**: ตัดสินแล้ว 15 สิงหาคม 2569
- **ที่มา**: [issue #68](https://github.com/khthana/Deep-Portfolio/issues/68)
  รอบแรก (gradebook)
- **เกี่ยวข้อง**: [ADR-0028](0028-shared-api-types.md) คือใบที่ตั้ง
  `@deep-portfolio/api-types` ขึ้นมาและนำร่องด้วย course ใบนี้ไม่ได้ทบทวน
  การตัดสินใจของ ADR-0028 ข้อไหนเลย — มันตอบคำถามที่ ADR-0028 ไม่ได้ตอบ
  เพราะนำร่อง feature เดียวยังไม่เจอ

## บริบท

#68 คือ feature ที่เหลือทั้งหมด ทำทีละรอบ ADR-0028 บอกว่าแต่ละรอบต้องทำ*อะไร*
(ย้าย response type, ผูก service ฝั่ง API, ลบสำเนาฝั่ง web, รักษาพฤติกรรม)
แต่ไม่ได้บอกว่าเมื่อเจอสี่สถานการณ์ข้างล่างนี้ให้ตัดสินอย่างไร — เพราะ course
ไม่ได้เจอสักข้อ รอบ gradebook เจอครบทั้งสี่ในรอบเดียว จึงเขียนไว้ที่นี่ให้รอบ
ต่อ ๆ ไปไม่ต้องตัดสินซ้ำ

## การตัดสินใจ

**1. ชื่อใน package ต้องบอกว่าเป็นของ feature ไหน**

`index.ts` re-export ทุกอย่างออกไปเป็น namespace เดียวแบนราบ ชื่ออย่าง
`ActivityData` หรือ `StudentActivityData` จึงไม่ใช่แค่ชื่อที่คลุมเครือ แต่เป็น
ชื่อที่จะไปชนกับของ feature activity ตอนที่ feature นั้นย้ายมา รอบนี้จึงเปลี่ยน
ชื่อสามตัวตอนย้าย

| เดิม (สองฝั่งเขียนตรงกัน)  | ใน package                 |
| -------------------------- | -------------------------- |
| `StudentSubmittionData`    | `GradebookStudent`         |
| `StudentActivityData`      | `GradebookStudentActivity` |
| `ActivityData`             | `GradebookActivity`        |

การเปลี่ยนชื่อ type ไม่มีผลตอน runtime และรอบนี้แตะแค่บรรทัด import กับอีกสอง
บรรทัดใน `gradebook.service.ts` เพราะฝั่ง web ประกาศทั้งสามไว้แต่ไม่มีไฟล์ไหนเรียกใช้
ชื่อพวกนี้จากข้างนอกเลย ราคาถูกกว่านี้ไม่มีอีกแล้ว และมันจะแพงขึ้นทุกรอบที่
ปล่อยไว้ ส่วนชื่อระดับ response (`GradebookPerStudentResp`,
`GradebookPerActivityResp`) ไม่ต้องแตะ เพราะบอกอยู่แล้วว่าเป็นของใคร

**2. type ที่ใช้ข้าม feature อยู่ในไฟล์ของ feature ที่มันเป็นของ ไม่ใช่ไฟล์ของ
feature ที่บังเอิญย้ายก่อน**

`StudentActivityStatusDB` คือคอลัมน์ `student_activity.status` gradebook ส่งมัน
ก็จริง แต่มันไม่ใช่ของ gradebook รอบนี้จึงสร้าง
`packages/api-types/src/student-activity.ts` ขึ้นมาถือมันตัวเดียว พร้อมคอมเมนต์
ว่าที่เหลือของ feature นั้นยังไม่ย้าย ทางเลือกที่ไม่เอาคือยัดไว้ใน
`gradebook.ts` ก่อนแล้วค่อยย้าย ซึ่งแปลว่ารอบของ student-activity ต้องมาแก้
import ของ gradebook ด้วย — คือจ่ายสองรอบเพื่อประหยัดไฟล์เดียว

ชื่อยังเป็น `StudentActivityStatusDB` ตามที่ทั้งสองฝั่งเรียกกันอยู่ ทั้งที่คำว่า
DB ฟังดูขัดกับ package ที่เก็บรูปของสาย เหตุผลคือ `apps/api` มี
`StudentActivityStatus` อีกตัวที่มี `LATE` แทน `GRADING` ซึ่งเป็นการ*อ่าน*วันที่
ไม่ใช่คอลัมน์ และไม่ได้ออกสายไปตัวเดียวกัน คำต่อท้ายนี้คือสิ่งที่แยกสองตัวนั้น
ออกจากกัน การตัดทิ้งตอนที่ตัวหลังยังไม่ย้ายจะทำให้ไฟล์เดียวกันมีสองชื่อที่
เกือบเหมือนกันโดยไม่มีอะไรบอกว่าต่างกันตรงไหน

**3. ไฟล์ model ฝั่ง API ที่ว่างลงให้ลบ ไม่ต้องเหลือไว้ re-export**

`apps/api/src/models/gradebook.model.ts` ถูกลบทั้งไฟล์ ไม่ได้เหลือไว้ให้
`export type { … } from "@deep-portfolio/api-types"` เพราะ shim แบบนั้นคือการ
ทำให้มีสองทางที่ import สิ่งเดียวกันได้ ซึ่งรอบต่อไปจะเดาไม่ถูกว่าทางไหนคือทาง
ที่ตั้งใจ ไฟล์ที่เคย import จากมันแก้ให้ชี้ไปที่ package ตรง ๆ ในรอบเดียวกัน

ไฟล์ model ที่**ไม่**ว่าง (เช่น `student-activity.model.ts` ที่เหลือ type อื่น
อีกสิบกว่าตัว) ให้ลบเฉพาะตัวที่ย้าย แล้ว import ตัวนั้นกลับเข้ามาจาก package
ถ้าไฟล์นั้นยังใช้อยู่

**4. feature ที่ยังไม่ย้าย แต่ยืมรูปที่ย้ายไปแล้ว ต้องแก้ในรอบเดียวกัน**

`evaluation-service.service.ts` เรียก `getGradebookPerActivity` แล้ว spread แถว
ของมันทั้งแถวลงใน `StudentEvaluationData` พอ `deadline_date` ใน `GradebookActivity`
กลายเป็น string คอมไพเลอร์ก็ทักที่ `evaluation.model.ts` ทันที ทั้งที่ feature
evaluation ยังไม่ถึงคิว

รอบนี้แก้ `StudentEvaluationData.deadline_date` เป็น `string | null` ไปเลย
ไม่ใช่ cast กลับหรือแปลงเป็น `Date` เพื่อให้ type เดิมผ่าน เหตุผลคือ**ตอนนี้
รู้แล้วว่าของเดิมผิด** — endpoint นั้นส่ง string มาตลอด และการเขียน `Date` ไว้
ต่อทั้งที่รู้ คือการเขียนข้อความที่รู้ว่าไม่จริงลงไปในไฟล์ ซึ่งเป็นสิ่งเดียวกับ
ที่ #61 มาแก้ ส่วนที่เหลือของ `StudentEvaluationData` ยังไม่แตะ และรอรอบของมัน

`StudentEvaluationData` มีฝาแฝดฝั่ง web ที่
`apps/web/src/features/student/course/types/course-type.ts` ซึ่งคอมไพเลอร์
**ไม่**ทัก เพราะเป็นคนละไฟล์คนละการประกาศ รอบนี้แก้ให้ด้วย ด้วยเหตุผลเดียวกัน
เป๊ะ ๆ กติกาข้อนี้จึงอ่านว่า "รูปที่ยืมมา" ไม่ใช่ "ที่ที่คอมไพเลอร์ทัก" — ถ้าแก้
เฉพาะฝั่งที่ทัก จะเหลือชื่อเดียวกันสองไฟล์ที่พูดไม่ตรงกัน ซึ่งแย่กว่าตอนที่ทั้ง
สองผิดเหมือนกัน

**5. helper ฝั่ง web ที่รับวันที่ ให้ขยาย ไม่ใช่บีบ**

`convertDateToThaiFormat` รับ `Date | null` แต่วันที่ที่ผู้เรียกทั้ง 22 จุดเอามา
แสดงล้วนมาจาก JSON — เป็น string มาตลอด ไม่ว่า type จะเขียนว่าอะไร รอบนี้ขยายเป็น
`Date | string | null` ไม่ใช่บีบเป็น `string | null` ด้วยสองเหตุผล หนึ่ง การบีบ
จะทำให้ 21 จุดของ feature ที่ยังไม่ย้ายพังพร้อมกัน คือลาก #68 ทั้งใบมาไว้ในรอบ
เดียว สอง มีสองจุดที่ห่อด้วย `new Date()` เองก่อนเรียก (popup ของปฏิทินทั้งสอง
ตัว) ตอน runtime จึงเป็น `Date` จริง ๆ ครึ่ง `Date` ของ union ไม่ได้มีไว้รอ
feature อย่างเดียว แต่มีผู้เรียกอยู่ตอนนี้ด้วย

## สิ่งที่รอบนี้เจอ ตรงกับที่ #68 เดาไว้

`deadline_date` คือแบบที่ 1 ในสามแบบที่ #68 เตือน (web เขียน `Date` แต่ JSON ส่ง
string) ไม่เจอแบบที่ 2 และ 3 ในรอบนี้ — สำเนาฝั่ง web ของ gradebook ตรงกับฝั่ง
API ทุกฟิลด์ที่เหลือ ซึ่งไม่แปลก เพราะฝั่ง API มีไฟล์ model ของ feature นี้อยู่
แล้ว และสองไฟล์นั้นถูกเขียนคู่กันมา

`gradebook.service.ts` เขียน `deadline_date` ออกมาเป็น `toISOString()` เอง ด้วย
เหตุผลเดียวกับ `getCLO`/`getPLOList` ใน ADR-0028 — `JSON.stringify` เรียก
`toJSON()` ของ `Date` ซึ่งก็คือ `toISOString()` อยู่แล้ว response จึงเหมือนเดิม
ทุกไบต์ และมีเคสที่รอยต่อ HTTP ยืนยันว่าฟิลด์นี้เป็น string รูป ISO จริง ไม่มี
อะไรลง `BEHAVIOR-CHANGES.md`

## ผลที่ตามมา

- เหลือสำเนาฝั่ง web 38 ไฟล์ 2,136 บรรทัด (จาก 2,172 หลัง #61) — ไฟล์ยังเท่าเดิม
  เพราะ `gradebook-type.type.ts` ยังอยู่ ถือรูปของแถวในตาราง antd ซึ่งไม่ใช่รูป
  ของ response
- รอบต่อไปไม่ต้องตัดสินห้าข้อข้างบนใหม่ ถ้าเจอสถานการณ์ที่ห้าข้อนี้ไม่ครอบคลุม
  ให้เขียน ADR ใบใหม่ อย่าแก้ใบนี้ย้อนหลัง
- ตัวเลือกที่ ADR นี้ไม่เอาไว้ทั้งสามข้อ (shim, ยัด type ข้าม feature ไว้ก่อน,
  บีบ helper) มีอย่างเดียวที่เหมือนกัน: มันย้ายงานไปให้รอบหลัง โดยที่รอบหลัง
  ไม่มีอะไรบอกว่ามีงานค้างอยู่
