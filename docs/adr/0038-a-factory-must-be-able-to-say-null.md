# ADR-0038 — factory ต้องพูดคำว่า null ได้ ไม่งั้นเคสที่พิสูจน์ type ก็เขียนไม่ได้

- **สถานะ**: ตัดสินแล้ว 19 สิงหาคม 2569
- **ที่มา**: [issue #68](https://github.com/khthana/Deep-Portfolio/issues/68)
  รอบ course-material
- **เกี่ยวข้อง**: [ADR-0029](0029-api-types-per-feature.md) ข้อ 3 (ไฟล์ที่ว่างลง
  ให้ลบ) กับข้อ 4 (คนที่ยืมรูปต้องตามในรอบเดียวกัน) ซึ่งรอบนี้ใช้ทั้งสองข้อ,
  [ADR-0033](0033-learning-activity-and-the-absent-key.md) เรื่องคีย์ที่หายไป
  ต่างจากคีย์ที่เป็น null, [ADR-0035](0035-one-group-shape-for-both-halves.md)
  ข้อ 2 เรื่องชื่อที่บอกรูปไม่ใช่บอกเส้น และ
  [ADR-0036](0036-a-bare-scalar-gets-no-name.md) ข้อ 4 เรื่องค่า null ที่ไปจบ
  ที่จุด map ฝั่ง UI ใบนี้ไม่ได้ทบทวนข้อไหนของสี่ใบนั้น — มันตอบคำถามที่ยังไม่มี
  ใครถาม คือ **ถ้า factory เขียนค่า null ไม่ได้ จะเขียนเคสที่พิสูจน์ type อย่างไร**

## บริบท

`/course-material` มีสามเส้น และมีรูปเดียว: `GET` ตอบแถวละสัปดาห์ ส่วน `POST`
กับ `DELETE` ไม่มีคีย์ `data` เลย — service ไม่ได้คืนอะไร และ `JSON.stringify`
ทิ้งคีย์ที่มีค่าเป็น `undefined` ไป ไม่ได้ส่งเป็น null (ADR-0033) รอบนี้ปักไว้ด้วย
`not.toHaveProperty("data")` ทั้งสองเส้น ทั้งคู่จึงไม่มี type และไม่ใช่การลืม

เส้น `GET` มี `as GetCourseMaterialDetailResp[]` ครอบผลลัพธ์ทั้งก้อน แบบเดียวกับ
ที่ ADR-0032 เจอ และมันปิดของไว้หนึ่งอย่าง

## สิ่งที่ `as` ปิดไว้

| จุด                       | type เดิมบอก        | ของจริง                             |
| ------------------------- | ------------------- | ----------------------------------- |
| `title`                   | `string` ทั้งสองฝั่ง | `course_syllabus.title` เป็น `String?` |
| return ของ service        | `… [] \| null`      | คืน array เสมอ ไม่เคยคืน null        |

`week_no` ที่อยู่ข้าง ๆ กันเป็น `Int` ไม่ยอม null จริง ๆ — สอง field ที่ `select`
มาด้วยกันแต่ nullable ไม่เหมือนกัน ซึ่งเป็นเหตุผลที่ต้องเปิด schema อ่าน ไม่ใช่
เดาจากว่ามันอยู่บรรทัดติดกัน

## การตัดสินใจ

**1. factory ที่ปิดทางค่า null อยู่ ให้ขยาย ไม่ใช่เลี่ยงไปเรียก prisma ตรง ๆ**

เคสที่พิสูจน์ว่า `title` เป็น null ได้ ต้องสร้างสัปดาห์ที่ไม่มีชื่อ แต่
`createLessonPlan` เขียนไว้ว่า

```ts
title?: string;
// …
title: options.title ?? "หัวข้อประจำสัปดาห์",
```

`?? ` ตัวนั้นแปลว่า "ไม่ส่งมา" กับ "ส่ง null มา" ลงเอยเหมือนกัน คือได้ค่า default
เคสจึงเขียนไม่ได้เลยไม่ว่าจะพยายามอย่างไร

ทางเลือกที่ไม่เอาคือให้เคสเรียก `prisma.course_syllabus.create` เอง ซึ่งขัดกับ
กติกาใน `CLAUDE.md` ที่ว่าข้อมูลมาจาก factory และจะทำให้เคสที่สำคัญที่สุดของรอบ
เป็นเคสเดียวที่ไม่ผ่าน factory — คนอ่านคนต่อไปจะไม่รู้ว่าทำไม

รอบนี้จึงขยาย option เป็น `title?: string | null` แล้วเปลี่ยน `??` เป็นการเทียบ
`undefined` ตรง ๆ ผลคือ "ไม่ส่ง" ยังได้ default เหมือนเดิมทุกเคสที่มีอยู่ ส่วน
"ส่ง null" เพิ่งเขียนได้เป็นครั้งแรก

**กติกาที่ตามมา**: ทุกคอลัมน์ที่ nullable และมีเคสจะพิสูจน์มัน factory ต้องแยก
"ไม่ส่ง" ออกจาก "ส่ง null" ให้ได้ `??` บน option ที่คู่กับคอลัมน์ nullable จึงเป็น
กลิ่นไม่ดีตั้งแต่ต้น ไม่ใช่แค่ตอนที่มีคนมาต้องการ — และรอบที่เหลือของ #68 จะเจอ
เรื่องนี้อีกเรื่อย ๆ เพราะสิ่งที่รอบหนึ่ง ๆ ทำคือไล่ดูว่าคอลัมน์ไหนยอม null บ้าง

**2. `title` ที่เป็น null ไปจบที่ `?? ""` ที่จุด map ตาม ADR-0036 ข้อ 4**

`DataType.title` ของตารางเอกสารประกอบการสอนเป็น `string` การขยายมันเป็น
`string | null` จะลาก null เข้าไปในฟอร์มแก้ไขและ input ที่ผูกกับมัน รอบนี้จึงแปลง
ที่จุด map เหมือนที่รอบ score-weight ทำกับ `weight`

และเหตุผลก็เป็นแบบเดียวกัน คือ **null เขียนลงคอลัมน์นี้ไม่ได้เลยผ่านทางไหน**:
`addLessonPlanBody.title` กับ `updateLessonPlanBody.title` เป็น `text` ซึ่งบังคับ
ทั้งคู่ การเขียนตัวที่สาม (ตอนลบสัปดาห์แล้วเรียงเลขใหม่) แตะแค่ `week_no` และ
importer ไม่เขียนตาราง `course_syllabus` เลย คอลัมน์ยอม null ก็จริง แต่ไม่มีสายไหน
ใส่ให้

ต่างจากรอบ score-weight ตรงหนึ่งจุดที่ควรพูด: `weight` มี `@default(0)` ให้ยืม
เป็นค่าแทน ส่วน `title` ไม่มี default อะไรเลย `""` จึงเป็นการเลือกของหน้าจอ ไม่ใช่
ค่าที่ฐานข้อมูลบอก — ซึ่งเลือกได้เพราะไม่มีวันถูกใช้

**3. ชื่อใหม่ `CourseMaterialWeek` ตาม ADR-0035 ข้อ 2**

`GetCourseMaterialDetailResp` บอกว่าใครไปเอามา ไม่ได้บอกว่ามันเป็นอะไร สิ่งที่
มันเป็นคือ **หนึ่งสัปดาห์ของแผนการสอน พร้อมของที่แขวนไว้กับสัปดาห์นั้น** ชื่อใหม่
พูดแบบนั้น ส่วน `CourseMaterialDetail` (คู่ lecture/record) ไม่ต้องเปลี่ยน เพราะ
มันบอกอยู่แล้ว

**4. `lesson-plan.model.ts` ฝั่ง API ตามมาในรอบเดียวกัน**

`GetStudentLessonPlanWithMaterialResp` ฝัง `CourseMaterialDetail` ไว้ พอรูปนั้น
ย้าย คอมไพเลอร์ก็ทักที่ไฟล์นั้นทันที ทั้งที่ feature lesson-plan ยังไม่ถึงคิว
รอบนี้แก้ให้ชี้ไป package ตาม ADR-0029 ข้อ 4

ไม่มีอะไรใหม่ในข้อนี้ และเขียนไว้เพราะมันอ่านเหมือนใหม่ ก่อนรอบนี้มี model ฝั่ง
API สิบไฟล์ที่ import จาก package อยู่แล้ว และหลายไฟล์ก็อยู่ในสภาพเดียวกันเป๊ะ —
`student.model.ts` ยืม `Weekday` มาตั้งแต่รอบ course ทั้งที่ feature student ยังไม่
ย้าย และ `student-activity.model.ts` กับคู่แฝดของมันยืม `AttachmentDetailResp`
เหมือนกัน

สิ่งที่บันทึกไว้จึงเป็นสภาพ ไม่ใช่ความใหม่: มี model ของ feature ที่ยังไม่ถึงคิว
ถือขาข้างหนึ่งไว้ใน package ซึ่ง ADR-0029 ข้อ 4 สั่งให้ทำอยู่แล้ว และคอมเมนต์เหนือ
import บอกไว้ตรง ๆ ว่าที่เหลือของ type นั้นยังเขียนสองที่อยู่ คนอ่านจะได้ไม่คิดว่า
lesson-plan ย้ายแล้ว
