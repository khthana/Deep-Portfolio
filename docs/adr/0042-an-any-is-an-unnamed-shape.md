# ADR-0042 — `any` ฝั่ง web คือรูปที่ยังไม่มีใครตั้งชื่อ ไม่ใช่จุดที่ไม่ต้องมี type

- **สถานะ**: ตัดสินแล้ว 22 สิงหาคม 2569
- **ที่มา**: [issue #68](https://github.com/khthana/Deep-Portfolio/issues/68)
  รอบ portfolio-skill
- **เกี่ยวข้อง**: [issue #63](https://github.com/khthana/Deep-Portfolio/issues/63)
  ซึ่งเป็นเจ้าของการไล่ `any` ทั้งหมด ใบนี้ไม่ได้แย่งงานมาทำ แต่บอกว่ารอบของ #68
  ต้องทำอะไรเมื่อเดินไปเจอ `any` ที่เป็น response, [ADR-0037](0037-the-package-says-what-the-wire-says.md)
  เรื่อง package สะกดตามที่ออกสาย ใบนี้ใช้กติกาเดิมกับกรณีที่แปลกกว่าเดิม และ
  [ADR-0036](0036-a-bare-scalar-gets-no-name.md) ซึ่งตัดสินว่า**บาง** response
  ไม่ต้องมีชื่อ ใบนี้ต้องบอกให้ชัดว่าสองเรื่องนี้ไม่ใช่เรื่องเดียวกัน

## บริบท

ทักษะเป็น section ที่ใหญ่ที่สุดของ e-Portfolio: เก้าเส้นในขณะที่ section อื่นมี
ห้า เพราะทักษะกับชิ้นงานที่ใช้อ้างอิงถูกอ่านจากสองทิศทาง ชื่อของทักษะอยู่ที่
`portfolio_skill` ส่วนฟิลด์อื่นทั้งหมดอยู่ที่ `portfolio_skill_activity_mapping`
แถวละคู่ (ทักษะ, การส่งงาน)

ในเก้าเส้นนั้นมีเส้นหนึ่งที่ **ไม่มีใครประกาศรูปไว้เลยทั้งสองฝั่ง**:
`GET /portfolio-skill/mapping/:id` ฝั่ง API ไม่ได้เขียน return type ให้เมท็อดของ
มัน (เมท็อดเดียวใน service ที่ไม่มี) ส่วนฝั่ง web เขียนว่า

```ts
const resp = await axiosInstance.get<ResponseWrapper<any>>(…)
```

## การตัดสินใจ

**1. `any` ที่คร่อม response ไม่ใช่ "เส้นนี้ไม่ต้องมี type" — มันคือรูปที่ไม่มีใครอ่าน**

ADR-0036 ตัดสินไว้ว่า response ที่เป็นค่าเดี่ยวไม่ต้องตั้งชื่อ และรอบ ๆ ของ #68
ก็มีเส้นที่จงใจไม่มี type อยู่จริง (เส้นที่ตอบ `data: null`, `/options` ที่ตอบ
`{ label, value }`) ทั้งสองแบบนั้น**ตัดสินแล้วว่าไม่ตั้งชื่อ** ต่างจาก `any`
ตรงนี้ ซึ่งไม่มีใครตัดสินอะไรเลย

เส้นแบ่งที่ใช้: ถ้า endpoint ตอบ**วัตถุที่มีคีย์** และผู้เรียกต้องรู้ชื่อคีย์จึงจะ
ใช้ค่าได้ รูปนั้นต้องมีชื่อ `any` บอกว่าไม่มีใครเคยเปิดดูว่ามันตอบอะไร ซึ่งเป็น
คนละเรื่องกับการตัดสินใจไม่ตั้งชื่อ

**กติกาที่ตามมา**: รอบของ #68 ที่เดินไปเจอ `any` ที่คร่อม response **ตรงจุดที่
เรียก endpoint** — คือในไฟล์ service ฝั่ง web ของ feature นั้นเอง — ให้แก้ในรอบ
นั้น ไม่ต้องรอ #63 เพราะรอบนั้นกำลังอ่าน endpoint นั้นอยู่พอดี และ #63 ได้ตัวเลข
ลดลงฟรี (รอบนี้ warning ฝั่ง web ลดจาก 214 เหลือ 213)

เส้นแบ่งอยู่ที่**จุดที่เรียก** ไม่ใช่ที่ feature ที่เป็นเจ้าของข้อมูล ซึ่งต่างกัน
จริงในกรณีนี้: `use-portfolio.ts` ของรอบรวมเรียกทั้งแปด section แล้วประกาศผลของ
ทุกตัวเป็น `any[]` เพราะส่งผ่าน `cleanNullStr()` ซึ่งรับ `any` คืน `any` — และใน
ไฟล์เดียวกันยังมีสำเนา mapping เขียนมือไว้อีกชุด (`mappingItem as { … repository?:
string … }`) ที่ประกาศ nullability ผิดด้วย ทั้งหมดนั้นเป็นงานของ**รอบรวม** ไม่ใช่
ของรอบนี้: มันอยู่ในไฟล์ของ feature ที่ยังไม่ถึงคิว และแก้เฉพาะ `skillsData`
ตัวเดียวจากแปดตัวที่เขียนเหมือนกันหมดจะเป็นการทิ้งไฟล์ไว้ครึ่ง ๆ กลาง ๆ

ส่วน `any` ที่ไม่ใช่ response — พารามิเตอร์, ตัวแปรกลางทาง — ยังเป็นของ #63
ตามเดิม

**2. สิ่งที่ `any` ตัวนั้นปิดไว้: เส้นนี้ตอบแถวพร้อม "พ่อแม่" ของมันทั้งแถว**

`getPortfolioSkillMappingById` เขียนว่า `include: { portfolio_skill: true }`
คำตอบจึงเป็นสิบเอ็ดคอลัมน์ของ mapping บวกวัตถุ `portfolio_skill` ที่มี `id`,
`name` **และ `user_id`** ซ้อนอยู่ข้างใน

`user_id` ที่หลุดออกไปด้วยไม่ใช่ความบังเอิญที่ไร้เหตุผล: mapping ไม่มี `user_id`
ของตัวเอง การตรวจสิทธิ์จึงอ่านเจ้าของผ่านทักษะแม่ และ `include: true` ก็เอาทั้ง
แถวมา รอบนี้ตั้งชื่อให้ว่า `SkillMappingDetail` แล้วเขียนกำกับว่าทำไมคอลัมน์นั้น
ถึงอยู่ตรงนั้น ไม่ได้ตัดออก — การตัดคือการเปลี่ยนสิ่งที่ผู้เรียกเห็น ซึ่งไม่ใช่
งานของรอบย้าย type

เคสเดิมของเส้นนี้ใช้ `toMatchObject` กับสี่ฟิลด์ รอบนี้รัดเป็น `toEqual` ทั้งวัตถุ
ซึ่งเป็นสิ่งที่พิสูจน์ว่ารูปเป็นแบบนี้จริง ไม่ใช่แค่ว่า type ใหม่บอกอย่างนั้น

**3. `isShow*` สี่ตัวสะกดแบบ camelCase และ package ก็สะกดตาม**

`portfolio_skill_activity_mapping` ตั้งชื่อคอลัมน์แบบ camelCase คำตอบจึงมี
`isShowRepo` ปนอยู่กับ `student_activity_id` ในวัตถุเดียวกัน มีอีกตารางเดียวใน
ฐานข้อมูลที่ทำแบบนี้ คือ `portfolio` (`isShowPersonal`, `isShowAward`, …) ซึ่งเป็น
ตารางของรอบรวมที่ยังไม่ถึงคิว — สองตารางนี้เป็น 13 คอลัมน์ camelCase ทั้งหมดที่
schema มี และทั้งสองเป็นของ e-Portfolio

ADR-0037 ตัดสินไว้แล้วว่า package สะกดตามที่ออกสายจริง ไม่ใช่ตามธรรมเนียมของ
package ใบนั้นพูดถึง enum ใบนี้ยืนยันว่ากติกาเดียวกันใช้กับ**ชื่อฟิลด์** ด้วย
ไม่ใช่แค่ค่า — การเปลี่ยนเป็น `is_show_repo` ให้ดูเข้าชุดจะทำให้ type ไม่ตรงกับ
JSON ที่ผู้เรียกได้จริง

ต่างจาก `is_show_*` ของปริญญานิพนธ์ที่รอบที่แล้วเจอ ตรงที่ค่าของสี่ตัวนี้ไม่
เหมือนกันสองที่: ใน `SkillMapping` มันเป็น `boolean | null` ตามคอลัมน์ ส่วนใน
`PortfolioWorkDetail` เป็น `boolean` เพราะ service coalesce เป็น `false` (ค่า
default ของคอลัมน์เอง) ก่อนตอบ — สองเส้นอ่านตารางเดียวกันแล้วตอบไม่เหมือนกัน
package จึงต้องพูดทั้งสองอย่าง

**4. `mappings` ไม่ optional และเป็นครั้งที่สามที่คำถามนี้ตอบไม่เหมือนกัน**

สามรอบของ e-Portfolio เจอคีย์ที่ประกาศเป็น optional สามแบบ และคำตอบต่างกันหมด

| รอบ | คีย์ | ของจริง |
| --- | --- | --- |
| personal | `attachments` | เส้นเขียน**ไม่มีคีย์นี้เลย** จึงแยกเป็นสองรูป |
| หก section | `attachments` | มีเสมอ ไม่มีก็เป็นรายการว่าง |
| skill | `mappings` | มีเสมอ ไม่มีก็เป็นรายการว่าง |

ข้อสรุปคือ `?` ที่เขียนไว้ไม่เคยเป็นข้อมูล มันคือที่ว่างที่ต้องไปเปิด service อ่าน
เอาเองทุกครั้ง และคำตอบที่ได้ก็ไม่เหมือนกัน

ผลข้างเคียงที่จับต้องได้: `portfolio.service.ts` เขียน `(skill.mappings ?? [])`
ไว้ ซึ่งเป็น guard ที่อ่าน optional ที่ type แต่งขึ้นมาเอง รอบนี้ลบทิ้งได้

**5. เส้น `DELETE` ที่ฝั่ง web ประกาศว่าตอบแถว — เจอเป็นที่เจ็ดแล้ว**

`deletePortfolioSkill` เขียน `ResponseWrapper<PortfolioSkillDetail>` ทั้งที่
controller ตอบ `data: null` เหมือนอีกหกเส้นที่รอบที่แล้วเพิ่งแก้ไป

รูปแบบนี้เกิดจากคนเขียนหยิบ type ของ feature มาใส่ทุกเส้นโดยไม่ได้ดู controller
ทีละเส้น **ทุกรอบที่เหลือของ #68 ให้ไล่ดูเส้นเขียนทุกเส้นว่า controller ส่งอะไร
ไม่ใช่ดูว่า service คืนอะไร** — สองอย่างนี้ต่างกันได้ และใน e-Portfolio ต่างกัน
ทุกเส้นลบ

## ผลที่ตามมา

- เหลือสำเนาฝั่ง web **33 ไฟล์ 1,620 บรรทัด** (จาก 33 ไฟล์ 1,650 หลังรอบหก
  section) นับด้วย glob ชุดเดียวกับที่ ADR-0028 ประกาศไว้
- ในนั้น **14 ไฟล์ 570 บรรทัดยังเป็นของ e-Portfolio** และเก้าในสิบ router ย้ายครบ
  แล้ว **ที่เหลือในสิบสี่ไฟล์นั้นไม่มีบรรทัดไหนเป็นงานของ #68 เลย** แต่ก็ไม่ได้
  แบ่งตามโฟลเดอร์อย่างที่เดาได้: 212 บรรทัดเป็น view model ของเทมเพลต
  (ADR-0040 ข้อ 7) ที่เหลือเป็น request body กับ params, คอมเมนต์บอกทางที่รอบ
  ก่อน ๆ ทิ้งไว้, type ของข้อมูลตัวอย่างชื่อขึ้นต้นว่า `Mock*` และ enum ของ
  หน้าจอ (`ProgramType`) — ทั้ง `src/types/` และ
  `features/student/portfolio/types/` ต่างก็มี request body ปนอยู่ทั้งคู่ ไม่ใช่
  ว่าโฟลเดอร์หนึ่งเป็น request อีกโฟลเดอร์เป็น mock
- **และรอบรวมที่ยังเหลือก็ไม่ได้อยู่ใน glob นี้ด้วย** — สำเนาฝั่ง web ของมันคือ
  `PortfolioBackendResp` ซึ่งประกาศอยู่ใน
  `apps/web/src/services/portfolio.service.ts` ส่วนรูปที่เขียนคาไว้กลางฟังก์ชัน
  อยู่ใน `hooks/use-portfolio.ts` กับ `pages/e-portfolio/student-work-detail-page.tsx`
  ทั้งสามที่ไม่ใช่ไฟล์ type จำนวนบรรทัดที่ ADR-0028 ใช้วัดจึงนับไม่ติดมาตั้งแต่ต้น
  และรอบรวมจะทำให้ตัวเลขนี้แทบไม่ขยับ **ตัวเลขนี้วัดสิ่งที่มันวัดได้ ไม่ใช่งานที่
  เหลือทั้งหมด** ซึ่งเป็นข้อจำกัดที่ควรรู้ก่อนอ่านมันเป็นความคืบหน้า
- `npm run lint` ลดจาก 216 เหลือ **215 warning** (ฝั่ง web 213 ฝั่ง API 2) จาก
  `any` ตัวเดียวที่ข้อ 1 พูดถึง
- ไม่เพิ่มเคส (1,077 เคส API / 448 เคส web) แต่รัดสองเคสเดิม: เส้น
  `/mapping/:id` จาก `toMatchObject` สี่ฟิลด์เป็น `toEqual` ทั้งวัตถุ และเส้น
  `GET /portfolio-skill` ได้การไล่ชื่อคีย์ทั้งสี่ของแถวทักษะ ซึ่งเป็นสิ่งที่พิสูจน์
  ข้อ 4
- ไม่มีอะไรที่ผู้เรียกเห็นเปลี่ยน `BEHAVIOR-CHANGES.md` จึงไม่มีหัวข้อใหม่
