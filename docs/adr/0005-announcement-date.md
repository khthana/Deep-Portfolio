# ADR-0005 — งานที่ไม่มีวันประกาศ ถือว่าประกาศแล้ว

- **สถานะ**: ตัดสินแล้ว 10 สิงหาคม 2569
- **ที่มา**: [issue #29](https://github.com/khthana/Deep-Portfolio/issues/29)
  (พบระหว่างทำ #15)
- **เกี่ยวข้อง**: ไม่มี ADR ก่อนหน้าที่พูดถึงการมองเห็นงาน — สี่ ADR ก่อนหน้าว่าด้วยว่า
  **ใคร** กระทำกับอะไรได้ ไฟล์นี้ว่าด้วยว่า **เมื่อไหร่**

## บริบท

`announcement_date` คือวันที่งานชิ้นหนึ่งเปิดให้นักศึกษาเห็น ไม่ใช่แค่วันประกาศผล
คะแนน — `isAnnounced` (ชื่อเดิม `checkIsOverAnnouncementDate` ดูท้ายไฟล์)
เป็นประตูของ 5 route ฝั่งนักศึกษา

- `GET /student/calendar` — ปฏิทิน
- `GET /lesson-plan/student` — รายชื่องานในแต่ละสัปดาห์
- `GET /student/classwork/list` — งานของกลุ่มเรียนหนึ่ง แยกตามหมวดคะแนน
- `GET /student/all/classwork/list` — งานของทุกกลุ่มเรียน แยกเป็นเลยกำหนด/
  สัปดาห์นี้/กำลังจะถึง/ส่งแล้ว
- `GET /evaluation/list` — คะแนนของตัวเอง

ทั้งห้าเรียกฟังก์ชันตัวเดียวกัน และสี่ในห้าเรียกสองครั้ง — ครั้งหนึ่งสำหรับ
`activities` อีกครั้งสำหรับ `learning_activities`

ของเดิมอ่านค่าว่างว่า "ยังไม่ถึงวันประกาศ" (`if (!announcement) return false`)
แต่ `announcement_date` เป็น optional ทุกที่ที่เขียนลงไป — ทั้ง
`activity.schema.ts` และ `learning-activity.schema.ts` ใช้ `optionalDate` และ
คอลัมน์ใน schema ก็ nullable ผลคืองานที่อาจารย์ไม่ได้กรอกช่องนี้ **ไม่มีวันปรากฏ
ให้นักศึกษาเห็นเลย** ต่อให้ตรวจเสร็จนานแล้ว และไม่มีอะไรบอกทั้งสองฝ่ายว่าทำไม
อาจารย์เห็นงานของตัวเองครบทุกชิ้นในหน้าจอฝั่งอาจารย์ซึ่งไม่ผ่านประตูนี้

## สิ่งที่ต้องตัดสิน

ค่าว่างแปลว่าอะไร มีสองทาง

1. **ประกาศทันที** — ไม่กรอก = เปิดให้เห็นตั้งแต่แรก
2. **บังคับกรอก** — ทำให้ `announcement_date` เป็น required ที่ API

## การตัดสิน

> ค่าว่างแปลว่า **ประกาศแล้ว** `isAnnounced(null)` คืน `true` ความหมายเดียวกัน
> ทั้งฝั่ง activity และ learning activity เพราะทั้งสองฝั่งเรียกฟังก์ชันตัวเดียวกัน

เลือกทางที่ 1 ด้วยเหตุผลสามข้อ

**การซ่อนต้องมีคนสั่ง** ประตูนี้มีไว้ให้อาจารย์เตรียมงานล่วงหน้าแล้วค่อยเปิด การ
ไม่กรอกวันไม่ใช่การสั่งให้ซ่อน มันคือการไม่ได้สั่งอะไรเลย และผลลัพธ์ที่ควรได้จาก
การไม่สั่งอะไรคือสถานะปกติ ไม่ใช่สถานะที่เข้มงวดที่สุดและกู้คืนไม่ได้เอง

**ทางที่ 2 ไม่ตอบคำถามที่ถาม** ต่อให้บังคับกรอกตั้งแต่วันนี้ แถวที่ค่าว่างอยู่แล้ว
ก็ยังต้องมีความหมายอยู่ดี ไม่งั้นมันติดค้างมองไม่เห็นตลอดไปเหมือนเดิม ทางที่ 2 จึง
เป็นงานเพิ่มบนคำตอบของทางที่ 1 ไม่ใช่ทางเลือกแทนกัน

**form ฝั่งเว็บบังคับกรอกอยู่แล้ว** ทั้ง `activity-detail-form.tsx` และ
`learning-activity-detail-form.tsx` ตั้ง `rules={[{ required: true }]}` ไว้ที่
ช่อง "วันประกาศ" งานที่สร้างผ่านหน้าจอจึงมีวันเสมอ ค่าว่างที่เหลือมาจากทางอื่น —
ข้อมูลเดิม หรือการยิง API ตรง — ซึ่งเป็นกรณีที่ ADR นี้ให้ความหมาย

### ไม่บังคับ `required` ที่ API

`optionalDate` ใน schema ทั้งสองไฟล์ยังอยู่เหมือนเดิม การเปลี่ยนเป็น required
จะทำให้ `POST`/`PATCH` ที่ไม่ส่ง field นี้ได้ `400` ซึ่งเป็นการเปลี่ยน contract
ของ endpoint โดยที่ปัญหาใน #29 ถูกแก้ไปแล้วด้วยการตัดสินข้างบน — ไม่มีงานชิ้นไหน
หายไปจากสายตานักศึกษาอีกไม่ว่าจะกรอกหรือไม่กรอก

### ไม่ต้อง backfill ข้อมูลเดิม

ผลตามมาโดยตรงของการตัดสิน แถวที่ `announcement_date` เป็น `NULL` อ่านได้ทันทีว่า
ประกาศแล้ว จึงไม่มี migration ให้เขียนและไม่มีวันที่ต้องเดาย้อนหลังให้ข้อมูลเดิม

## ผลที่ตามมา

- นักศึกษาเห็นงานที่ไม่มีวันประกาศทุกหน้าจอที่เคยซ่อนไว้ ดู
  [`BEHAVIOR-CHANGES.md`](../../BEHAVIOR-CHANGES.md)
- **ฟังก์ชันเปลี่ยนชื่อเป็น `isAnnounced`** อยู่ที่
  `apps/api/src/utils/is-announced.ts` ชื่อเดิม `checkIsOverAnnouncementDate`
  บอกวิธี ไม่ได้บอกคำตอบ และหลังการตัดสินข้างบนมันก็ผิดด้วย — ไม่มีอะไร "เลย"
  วันที่ไม่เคยมี ทั้งที่คำตอบคือใช่ จุดเรียกทั้งสิบใน 5 service อ่านได้ตรงตัวขึ้น
  เป็นการเปลี่ยนชื่อล้วน ๆ ผู้เรียก HTTP ไม่เห็นอะไร
- **การซ่อนงานยังทำได้เหมือนเดิม** ด้วยการตั้งวันประกาศไว้ในอนาคต ซึ่งเป็นวิธีที่
  หน้าจอใช้อยู่แล้ว ที่หายไปคือการซ่อนโดยไม่ได้ตั้งใจเท่านั้น
- ฟังก์ชันนี้ตัดสินการมองเห็น **ทั้งชิ้นงาน** ไม่ใช่แค่คะแนน อาจารย์ที่อยากให้
  นักศึกษาเห็นโจทย์ก่อนแล้วค่อยเห็นคะแนน ทำไม่ได้ด้วยช่องเดียวนี้ ทั้งก่อนและหลัง
  #29 — ถ้าจะแยกสองอย่างต้องมีคอลัมน์ที่สอง และเป็นคำถามที่ยังไม่มีใครถาม

## จะกลับมาทบทวนเมื่อไหร่

เมื่อมีคนขอให้ "งานที่ยังไม่พร้อม" เป็นสถานะที่ตั้งใจได้โดยไม่ต้องผูกกับวัน — เช่น
ฉบับร่าง ตอนนั้นสิ่งที่ต้องเพิ่มคือสถานะของงาน ไม่ใช่การกลับไปอ่านค่าว่างว่าซ่อน
