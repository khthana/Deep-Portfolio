# การนำเข้า master data

master data 28 ตารางของระบบไม่มีหน้าจอหรือ API สำหรับเพิ่มข้อมูล — คณะ ภาควิชา
หลักสูตร รายวิชา อาจารย์ นักศึกษา PLO/CLO rubric ทั้งหมดนี้ต้องใส่เข้าไปก่อนที่
ระบบจะใช้งานได้จริง เอกสารนี้อธิบายวิธีใส่ด้วยคำสั่ง `import`

ที่มา: [D7 ของ spec](spec-refactor-redeploy.md#d7--เครื่องมือนำเข้าข้อมูล) และ
[issue #23](https://github.com/khthana/Deep-Portfolio/issues/23)

## วิธีใช้

เตรียมโฟลเดอร์ที่มีไฟล์ `.csv` แล้วสั่ง

```
npm run import --workspace @deep-portfolio/api -- ./data
```

ถ้าข้อมูลถูกต้องทั้งหมด จะเขียนลงฐานข้อมูลแล้วรายงานว่าเพิ่ม/อัปเดตตารางละกี่รายการ
ถ้ามีอะไรผิดแม้แต่จุดเดียว **จะไม่เขียนอะไรลงฐานข้อมูลเลย** และรายงานว่าผิดที่ไฟล์ไหน
บรรทัดไหน คอลัมน์ไหน — แก้แล้วสั่งใหม่ได้ทันที

คำสั่งนี้อ่านค่า `DATABASE_URL` จาก environment เหมือนตัว API ถ้ารันด้วย Docker
ให้เข้าไปสั่งในคอนเทนเนอร์ของ API และวางโฟลเดอร์ข้อมูลไว้ในที่ที่คอนเทนเนอร์เห็น

## รูปแบบไฟล์

- ไฟล์ละหนึ่งตาราง **ตั้งชื่อไฟล์ตามชื่อตาราง** เช่น `faculty.csv`, `subjects.csv`
  ชื่อไฟล์ที่ไม่ตรงกับตารางใดจะถูกปฏิเสธ (กันสะกดผิดแล้วข้อมูลหายเงียบ ๆ)
- ไฟล์เป็น CSV — ใน Excel เลือก **บันทึกเป็น → CSV UTF-8 (มีตัวคั่นเป็นจุลภาค)**
  ตัวอ่านรองรับ BOM, ท้ายบรรทัดแบบ Windows, และช่องที่ครอบด้วยเครื่องหมายคำพูดซึ่งมี
  จุลภาคหรือขึ้นบรรทัดใหม่อยู่ข้างใน
- **บรรทัดแรกคือชื่อคอลัมน์** สะกดตรงตามชื่อคอลัมน์ในฐานข้อมูล ไม่ใช่ชื่อภาษาไทย
- ลำดับคอลัมน์ไม่สำคัญ บรรทัดว่างถูกข้าม
- ไม่ต้องใส่ครบทุกคอลัมน์ ใส่เฉพาะที่มีข้อมูล — ดูตารางอ้างอิงข้างล่างว่าคอลัมน์ไหน
  จำเป็น

ตัวอย่าง `faculty.csv`

```csv
faculty_id,faculty_name_th,faculty_name_en
01,คณะวิศวกรรมศาสตร์,Faculty of Engineering
```

## กฎที่ควรรู้ก่อนรันจริง

**ตรวจก่อนเขียนทั้งหมด** — ทุกไฟล์ถูกอ่านและตรวจจนจบก่อนจะเขียนแถวแรก และการเขียน
ทั้งหมดอยู่ใน transaction เดียว จึงไม่มีสภาพ "เข้าไปได้ครึ่งไฟล์" ให้ต้องตามเก็บ

**เรียงลำดับตาม foreign key ให้เอง** — ไม่ต้องแบ่งรันเป็นรอบ ๆ วางไฟล์ทั้งหมดไว้ใน
โฟลเดอร์เดียว ตัวนำเข้าจะเขียน `faculty` ก่อน `departments` ก่อน `programs` เอง และ
ค่าที่อ้างถึงจะถือว่าถูกต้องถ้ามีอยู่ในฐานข้อมูลแล้ว **หรือ** กำลังจะถูกเขียนในรอบเดียวกัน

**รันซ้ำได้** — แต่ละตารางมี "คีย์" ที่ใช้ดูว่าแถวที่เข้ามาเป็นแถวใหม่หรือแถวเดิม
(ดูตารางอ้างอิง) แถวที่คีย์ซ้ำกับของเดิมจะถูก **อัปเดต** ไม่ใช่เพิ่มใหม่ ดังนั้นแก้ไฟล์
แล้วรันซ้ำได้เรื่อย ๆ และรันไฟล์เดิมสองครั้งได้จำนวนแถวเท่าเดิม

**ช่องว่างแปลว่า "ไม่แตะคอลัมน์นี้"** ไม่ใช่ "ล้างค่าให้ว่าง" — ไฟล์ที่กรอกไม่ครบจึงไม่
ลบสิ่งที่ไฟล์ก่อนหน้าใส่ไว้ ถ้าต้องการล้างค่าจริง ๆ ต้องแก้ในฐานข้อมูลเอง

**ค่าซ้ำในไฟล์เดียวกันถูกปฏิเสธ** — สองแถวที่คีย์เดียวกันในไฟล์เดียวจะถูกรายงาน พร้อม
บอกว่าไปซ้ำกับบรรทัดไหน

คอลัมน์อื่นของแต่ละตารางใส่หรือไม่ใส่ก็ได้ ชื่อและชนิดทั้งหมดดูได้จาก
`apps/api/prisma/schema.prisma` ซึ่งเป็นแหล่งความจริงของ schema — ตัวนำเข้าอ่าน
รายการคอลัมน์ ความยาวสูงสุด และ foreign key จากไฟล์นั้นโดยตรง ไม่ได้เก็บสำเนาไว้
เพิ่มคอลัมน์ใน schema แล้วตัวนำเข้ารับคอลัมน์นั้นทันทีโดยไม่ต้องแก้โค้ด

### ข้อควรระวังที่เจอบ่อย

- **นักศึกษาต้องเป็น `users` ก่อน** — `student.student_id` เป็น foreign key ไปที่
  `users.user_id` รหัสอาจารย์กับรหัสนักศึกษาอยู่ในพื้นที่รหัสเดียวกัน ดังนั้นไฟล์
  `student.csv` ต้องมาคู่กับ `users.csv` ที่มีรหัสเดียวกัน (วางไว้โฟลเดอร์เดียวกันได้เลย)
- **`roles` ต้องนำเข้าเป็นอย่างแรก** — migration สร้างแต่ตารางเปล่า ไม่ได้ใส่ข้อมูลใด ๆ
  ให้ และโค้ดเปรียบเทียบ `role_id` เป็นข้อความตรง ๆ (`requireRole("TEACHER")`)
  ค่าที่ระบบใช้จริงมี 7 ค่า เรียงตาม `priority` 1–7 คือ `FULL_ADMIN`,
  `FACULTY_ADMIN`, `DEPT_ADMIN`, `PROG_MANAGER`, `TEACHER`, `STUDENT`, `GUEST`
  — สะกดตามนี้เท่านั้น
- **`user_roles` คือที่ที่กำหนดสิทธิ์** — คนที่ไม่มีแถวใน `user_roles` เข้าระบบได้แต่
  ทำอะไรไม่ได้ ค่า `role_id` ต้องตรงกับ `roles.role_id`
- **`departments.department_id` กว้าง 2 ตัวอักษร** ขณะที่ `subjects.department_id`
  กว้าง 20 — ความไม่สมมาตรนี้เป็นของ schema เดิม ให้ใส่รหัสภาควิชา 2 หลักทั้งคู่
- **`learning_outcomes.parent_outcome_id` ชี้ไปที่แถวในไฟล์เดียวกันไม่ได้** — คอลัมน์นี้
  ชี้ไปที่ `outcome_id` ซึ่งฐานข้อมูลแจกเลขให้ตอนเขียน ไฟล์จึงไม่มีทางรู้เลขของแถวแม่ที่
  กำลังจะถูกเขียนพร้อมกันในรอบเดียวกัน ตัวนำเข้าจะฟ้อง
  `ไม่พบ ... ในตาราง learning_outcomes (คอลัมน์ outcome_id)` ให้เห็นก่อนเขียน
  **วิธีทำคือรันสองรอบ** รอบแรกนำเข้าแถวแม่ (PLO) โดยยังไม่ใส่คอลัมน์
  `parent_outcome_id` แล้วอ่านเลข `outcome_id` ที่ได้จริงจากฐานข้อมูล
  (`SELECT outcome_id, outcome_code FROM learning_outcomes`) จากนั้นเติมเลขนั้นลงไฟล์
  แล้วรันรอบที่สอง — แถวเดิมจะถูกอัปเดต ไม่ซ้ำ เพราะคีย์คือ `program_id, outcome_code`
  ไม่ใช่ `outcome_id`

## ตารางที่ไม่มีคีย์ตามธรรมชาติ

7 ตารางนี้ไม่มีคอลัมน์ใดหรือชุดคอลัมน์ใดที่ระบุแถวได้ นอกจาก `id` ที่ฐานข้อมูลแจกเอง
`activity_evidence`, `portfolio_template`, `rubric_details`, `student_group`,
`student_group_change_log`, `subject_clo_measurable_behavior`, `user_log`

ถ้าไฟล์ไม่ใส่ `id` มาเอง การรันซ้ำจะไม่มีทางรู้ว่าแถวที่เข้ามาคือแถวเดิม แล้วจะเพิ่ม
ข้อมูลซ้ำทั้งชุด — ตัวนำเข้าจึง **ปฏิเสธ** ไฟล์ของตารางเหล่านี้ที่ไม่มีคอลัมน์ `id`
ถ้าจะนำเข้าจริงต้องกำหนดเลข `id` ในไฟล์เองและใช้เลขเดิมทุกครั้งที่รันซ้ำ

## คอลัมน์ที่ฐานข้อมูลคำนวณเอง

สองคอลัมน์นี้ Postgres คำนวณจากคอลัมน์อื่นในแถวเดียวกัน และปฏิเสธการเขียนที่เอ่ยถึงมัน

| คอลัมน์ | คำนวณจาก |
|---|---|
| `student.full_name_th` | `first_name_th` + `last_name_th` |
| `student.admission_year` | สองหลักแรกของ `student_id` + 2500 |

ไฟล์รายชื่อนักศึกษาที่ export มามักติดคอลัมน์ชื่อเต็มมาด้วย — ถ้าติดมา ตัวนำเข้าจะบอก
ให้ลบคอลัมน์นั้นออก ไม่ต้องกรอกอะไรแทน เพราะค่าจะถูกเติมให้เองหลังเขียน

## กติกาการกำหนด `users.user_id` ของอาจารย์

`users.user_id` กว้าง 8 ตัวอักษร และเป็นพื้นที่รหัสเดียวกับรหัสนักศึกษา รหัสอาจารย์
จึงกำหนดเป็น

```
[รหัสคณะ 2 หลัก][รหัสภาควิชา 2 หลัก][ลำดับในภาควิชา 4 หลัก]
```

เช่น อาจารย์คนแรกของภาควิชาวิศวกรรมคอมพิวเตอร์ (คณะ `01` ภาควิชา `05`) คือ
`01050001` รูปแบบนี้ต่อเนื่องกับรหัสหลักสูตรที่ใช้อยู่แล้ว (`01050101`,
`01050102`) และไม่ชนกับรหัสนักศึกษา เพราะรหัสนักศึกษาขึ้นต้นด้วยสองหลักท้ายของ
ปีการศึกษาที่เข้า (`65`, `66`, …) ซึ่งไม่มีทางเป็นรหัสคณะ

ลำดับ 4 หลักเดินต่อไปเรื่อย ๆ ภายในภาควิชา และ **ห้ามนำรหัสของคนที่ลาออกมาใช้ซ้ำ**
เพราะรหัสนี้ผูกกับประวัติการสอนและ log ทั้งหมดของคนคนนั้น

## ข้อความผิดพลาดที่พบบ่อย

| ข้อความ | ความหมาย |
|---|---|
| `ต้องมีคอลัมน์นี้ในไฟล์` | ไฟล์ขาดคอลัมน์ที่ตารางบังคับ ดูตารางอ้างอิง |
| `ไม่มีคอลัมน์นี้ในตาราง …` | สะกดชื่อคอลัมน์ผิด หรือใช้ชื่อภาษาไทยเป็นหัวตาราง |
| `ไม่พบ … ในตาราง … (คอลัมน์ …)` | ค่าที่อ้างถึงยังไม่มี — ใส่ไฟล์ของตารางนั้นเพิ่มในโฟลเดอร์ หรือแก้ค่าให้ถูก |
| `ซ้ำกับแถวบรรทัดที่ …` | สองแถวในไฟล์เดียวกันมีคีย์เดียวกัน |
| `ต้องยาวไม่เกิน N ตัวอักษร` | ค่ายาวเกินความกว้างของคอลัมน์ นับเป็นตัวอักษร ไม่ใช่ไบต์ |
| `ต้องเป็นค่าใดค่าหนึ่งใน: …` | คอลัมน์เป็น enum รับได้เฉพาะค่าที่ระบุ |
| `มี N ช่อง แต่หัวตารางมี M คอลัมน์` | แถวมีจำนวนช่องไม่ตรงกับหัวตาราง มักเกิดจากจุลภาคในข้อความที่ไม่ได้ครอบด้วยเครื่องหมายคำพูด |
| `ฐานข้อมูลคำนวณคอลัมน์นี้เอง …` | ดูหัวข้อ "คอลัมน์ที่ฐานข้อมูลคำนวณเอง" |
